## 更新概述

这一天做了三件事：后台的"远程图床"正式退场，改由独立的本地图床管理器「洛佬の美图」接手，后台只负责跳转与探活；全站滚动锁从头重写，不再改动 `body` 的 `overflow`，彻底解决"弹窗一开右侧 sticky 卡片消失"和"关闭后回到页面顶部"两个顽疾；同时修掉搜索摘要高亮整体左移、播放器封面暂停瞬间回正两个视觉问题。

## 主要变更

### 图床管理器接管远程图床

- **背景**：后台原有的远程图床依赖 GitHub Token 与 `githubApi` 服务，能力受限于 GitHub 的目录与频率限制，且 Token 需要长期存放在浏览器会话中。独立的本地图床管理器自带批量上传、自动分类归档、重复检测、批量取链与 Git 同步，能力更完整，后台没必要再自带一套
- **地址可配置**：管理器默认地址为 `http://127.0.0.1:3210`，保存在 localStorage（键名 `admin_gallery_manager_url`）。用户只填 `127.0.0.1:3210` 时自动补 `http://`，末尾多余斜杠会被规范化；仅接受 `http`/`https` 协议，防止 `javascript:` 之类危险协议被塞进 `href`
- **在线探活**：请求管理器不校验令牌的 `/api/health`，用 `mode: 'no-cors'` + `AbortController`（默认 2.5 秒超时）。管理器未开 CORS，响应内容读不到，但只要 fetch 正常 resolve 就说明端口有服务在监听
- **进程启停**：后台 Server Action 支持一键启动/关闭管理器。启动走源码方式（`manager/server.js`），路径固定、行为可预期；关闭优先用启动时记录的 PID（写在 `.next/cache/gallery-manager.pid`），记录缺失时按端口反查监听进程，并在 `taskkill` 前校验命令行，确认是图床管理器才动手，避免误杀占用同端口的其他程序
- **useGallery 瘦身**：原 Hook 里 600 余行 GitHub 远程逻辑（上传、删除、目录浏览）全部移除，只保留本地图床（`public` 目录）的浏览、上传与删除，不留永不执行的死分支
- **CSP 放行**：`cspSources.ts` 增加 `http://127.0.0.1:*` 到 `connect-src`。不放行时探活请求会被 CSP 静默拦截，页面永远显示"未启动"。该规则仅覆盖本机回环地址，不扩大对外暴露面
- **静态导出兼容**：新增的 `galleryManagerActions` 纳入静态导出的空实现机制（`index.static.ts` 同步补齐，`prepare-static-export.js` 的替换清单增加该文件），保证 `build:pages` 不会因新 Action 报错

### 滚动锁重写

- **旧实现的两个副作用**：直接给 `body` 设置 `overflow: hidden` 会让 `body` 变成滚动容器，全站 `position: sticky` 元素失去粘性、回落到文档流原位——用户已经滚到页面中段时，这些元素落在视口之外，看起来就是"点开弹窗后右侧卡片消失"；部分浏览器在恢复 `overflow` 后还会把文档滚动位置重置为 0，表现为"关闭弹窗后回到顶部"
- **新实现不改布局样式**：完全不碰 `overflow` / `position` / `padding`，改为锁定瞬间记录滚动位置，锁定期间持续守护，解锁时精确还原
- **事件拦截而非滚动禁止**：只拦截"背景区域"的滚轮、`touchmove` 与键盘滚动（空格、PageUp/PageDown、方向键、Home/End）。事件目标位于固定定位弹层内、位于可滚动区域内，或落在输入框/文本域/下拉框/富文本上时一律放行，保证弹窗自身滚动、图片滚轮缩放、拖拽与输入正常
- **引用计数**：同时打开的弹层数量归零才真正解除锁定，搜索弹窗与外链提醒叠加时不会提前解锁
- **位置守护**：`scroll` 监听把滚动位置持续拉回（容差 1px），解锁时再还原一次；还原直接给 `scrollingElement.scrollTop` 赋值，不调 `window.scrollTo`，避开平滑滚动造成的抖动
- **接入改造**：`AdminModal`、`AdminConfirm`、`ClientChangelogsPage` 全部改用该 Hook，移除各自手写的 `body` 溢出处理

### 搜索与播放器修复

- **HTML 实体解码**：搜索索引的 Markdown 清洗新增实体解码，覆盖 `&nbsp;`、`&emsp;`、`&ldquo;`、`&hellip;` 等常见命名实体与十进制/十六进制数字实体。此前只剥标签不解码，摘要里会把 `&emsp;` 原样显示出来；未识别的命名实体保持原样，避免误伤正文里的普通 `&`
- **摘要高亮偏移**：命中区间平移量的计算由 `start + 1` 改为 `start - prefix.length`。前缀省略号确实占 1 个字符，但正确方向是减不是加，原写法会让高亮整体左移 2 个字符
- **封面暂停不回正**：唱片封面改为始终挂 `animate-spin`，用 `animationPlayState: running / paused` 控制启停。原先暂停时移除动画类，`transform` 立刻归零，封面会"啪"地转回初始角度；现在暂停只是冻结在当前角度
- **移除冗余指示器**：删除封面上那层 hover 才出现的播放/暂停图标遮罩，封面本身已经能表达播放状态

## 使用方式

### 图床管理

1. 先在本机启动「洛佬の美图」管理器（或在后台点「启动管理器」，需已安装 `manager/node_modules`）
2. 进入后台「图床管理」页，地址栏默认 `http://127.0.0.1:3210`，状态显示「在线」即可点「打开管理器」跳转
3. 端口或路径不同时修改地址并保存，页面会立即重新探活；点「恢复默认」清除自定义配置

### 滚动锁调试

1. 任意弹窗打开后，右侧栏卡片应保持原位、不消失
2. 在弹窗内滚动内容区、用滚轮缩放图片均正常；在背景区域滚轮/触摸/空格滚动应被拦截
3. 关闭弹窗后页面停留在打开前的位置

## 注意事项

- 后台管理只在本地开发环境运行；生产（https 页面）访问 `http://127.0.0.1` 会被混合内容策略拦截，探活必然返回 false，这属于浏览器的正常限制，不影响线上功能
- 图床管理器的源码路径 `W:\Web\洛佬の美图\manager` 写死在 `galleryManagerProcess.ts`，换机或换目录时需同步修改
- 新增 Server Action 文件时务必同步加入 `prepare-static-export.js` 的替换清单，否则 `build:pages` 会在静态导出阶段报错
- 滚动锁依赖"弹层容器使用 `position: fixed`"这一项目约定；若新弹窗改用其他定位方式，其内部滚动会被误拦
- 搜索索引中的实体解码只处理实体本身，解码后的空白再由空白归并逻辑清理，两者不可拆分单独调整

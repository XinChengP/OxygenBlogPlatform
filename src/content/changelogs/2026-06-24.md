## 功能概述

本次更新重点重构了静态导出（Static Export）相关代码，统一 Server Actions 在静态模式下的空实现逻辑；音乐播放器改用 APlayer 原生循环模式替代自实现循环；后台管理 UI 整体梳理；Footer 备案信息进一步完善；相关链接页面新增页脚小鱼特效教程入口。

## 主要变更

### 静态导出与构建优化

- **新增构建前脚本**：在 `scripts/prepare-static-export.js` 中提供静态导出前的资源处理流程，自动将 Server Actions 替换为空实现，规避 Next.js 静态导出对 Actions 的限制
- **统一空实现逻辑**：在 `src/actions/index.static.ts` 中集中提供 `githubActions`、`settingsActions` 等模块在静态模式下的空实现，所有 `import` 在静态构建时被自动 alias 到该文件
- **actions 拆分文件恢复**：将 `.restored` 备份文件恢复为正式文件路径，确保版本管理中没有冗余文件残留
- **仪表盘统计适配**：`src/utils/server/adminStats.ts` 拆分为 server / client 兼容实现，静态导出环境下返回空数据，避免访问 `fs` 等 Node API 导致构建失败
- **管理员工具适配**：`src/utils/adminUtils.ts` 同步调整，移除静态导出下不可用的服务端 API
- **GitHub Actions 优化**：`src/actions/githubActions.ts` 与 `src/components/admin/DashboardClient.tsx` 适配新的空实现策略
- **package.json 脚本**：增加 `build:pages` 等脚本入口以触发静态导出准备流程

### 音乐播放器播放模式原生化

- **原生循环模式**：在 `useMusicPlayer.ts` 与 `MusicPlayer.tsx` 中将单曲循环改为 APlayer 原生 `loop: true` 配置，不再通过监听 `ended` 事件后重新调用 `play` 实现
- **类型扩展**：在 `src/types/aplayer.d.ts` 中补全 APlayer 循环相关类型声明，确保 TypeScript 严格模式下编译通过
- **APlayer 主题样式**：在 `src/components/aplayer-theme.css` 中补充循环模式激活态的视觉反馈
- **全局管理器同步**：`src/utils/globalMusicPlayerManager.ts` 同步切换到原生循环模式，避免出现"先循环再切下一首"的中间态
- **默认状态调整**：设置页中播放器默认状态由"开启"调整为"关闭"，需要用户主动开启后才会在页面显示

### Footer 备案信息完善

- **新增魔 ICP 备案链接**：在 `Footer.tsx` 中补充新备案信息，与既有"津ICP备"和"萌ICP备"并列展示
- **统一展示样式**：所有备案信息采用一致的小字号与文字阴影，保证在飞鱼特效背景上的可读性

### 后台管理 UI 梳理

- **多组件同步更新**：`AdminButton`、`AdminCard`、`AdminConfirm`、`AdminForm`、`AdminInput`、`AdminLayout`、`AdminLoading`、`AdminModal`、`AdminSearchBar`、`AdminSidebar`、`AdminTable`、`AdminToast`、`BackupManager` 等组件整体梳理，移除冗余样式与调试代码
- **Dashboard 适配**：`DashboardClient.tsx` 同步适配新的 actions 空实现
- **统一导出**：`src/components/admin/index.ts` 中按需重新导出组件，方便业务侧按模块引用

### 相关链接页面与博客更新

- **小鱼特效教程入口**：在 `RelatedLinks.tsx` 中新增飞鱼特效相关教程链接，方便用户参考实现
- **关于页配置更新**：在 `AboutSetting.ts` 中同步相关链接的展示数据
- **博客标签更新**：调整 `blogs-crash-diary.md` 文章标签，更符合当前博客分类体系

## 使用方式

### 静态构建与部署

1. 执行 `npm run build:pages` 触发静态导出流程
2. 脚本自动替换 Server Actions 为空实现并完成构建
3. 将 `out` 目录部署到 GitHub Pages 等静态托管平台

### 切换音乐循环模式

1. 播放任意歌曲，查看播放器控制按钮
2. 多次点击"循环模式"按钮，观察 `loop: single / list / off` 三种状态切换
3. 验证单曲循环时不再出现"先停止再恢复"的卡顿

## 注意事项

- 静态导出后所有 Server Actions 均不可调用，需要在客户端通过 GitHub API 直接请求
- 后台管理页面（`/admin/*`）在静态部署下仅作为本地开发使用，线上不会真正写入数据
- 单曲循环切换到原生模式后，原 `ended` 事件中的"切下一首"逻辑已迁移到"列表循环"分支，避免重复触发
- Footer 备案链接需确保对应的 `.well-known` 验证文件可公开访问

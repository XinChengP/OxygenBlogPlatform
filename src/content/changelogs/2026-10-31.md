## 更新概述

这一天把「更新日志」页面整体改名并重做成「开发日志」：页面标题、SEO 元数据、看板娘页面话术统一换成新名字（路由 `/changelogs` 不变），同时把 100+ 篇日志的信息架构重排——顶部加筛选栏（类型 + 年份双维度、计数互相联动），首屏只渲染 20 篇、滚动到底自动续载，卡片折叠态直接给出正文摘要、行数与字数，右侧统计图从「只读图表」变成「可点筛选器」。移动端另加一条可折叠的日志总览，因为原来两张统计图排在 100+ 篇日志之后基本没人能翻到。

同一轮里还修掉了前一天的三个尾巴：系统提示词第 3 条被重复插入、墨墨日期口径 Worker 与本地脚本各算一套、以及本地数据快照仍是旧口径。三点一起收掉后 `totalWords` 从 223 降到 179（旧口径把「仅加入计划、尚未学习的词」也算成已背）。

## 主要变更

### 页面更名与信息架构

- **文案统一**：`metadata` 的 title/description/keywords、Open Graph、Twitter 卡片全部从「更新日志」改为「开发日志」；看板娘页面联动话术 `'/changelogs': '更新日志'` 同步改为「开发日志」。关键词里保留「更新日志」作为次要词，避免丢失既有搜索词
- **代码高亮补齐**：日志正文在构建期由 rehype-highlight 生成 `hljs-*` 类名，但页面级没有引入高亮主题 CSS（博客详情页有）。直接访问 `/changelogs` 展开含代码块的日志时完全没有配色，现补 `highlight.js/styles/github-dark.css`
- **构建期摘要**：`getServerChangelogs` 额外计算 `excerpt`（正文纯文本约 110 字）、`lineCount`、`charCount`。`buildExcerpt` 只做「够用就好」的清洗：去代码块、图片、链接地址、标题/列表符号，折叠空白后截断。后台单篇读取不需要这些字段，因此全部保持可选

### 筛选与统计联动

- **双维度筛选**：新增 `ChangelogFilterBar`，类型 chip 与年份 chip 互不阻塞——切换年份时类型计数跟着刷新，切换类型时年份计数跟着刷新，用户能直接看到「再点一下还剩多少篇」，选中态用 `aria-pressed` 表达
- **图表当筛选器**：`TimeStatsChart` 新增 `onPeriodSelect` / `selectedPeriodLabel`，支持月/季/年三档粒度切换，点数据点即筛选列表，选中周期画一条 `ReferenceLine` 参考线，底部有操作提示；`TypeStatsChart` 新增 `onTypeSelect` / `selectedType`，点扇区或摘要项即按类型筛选，摘要项同步高亮
- **筛选状态可分享**：筛选回写到 URL query（`?type=fix&year=2026&period=2026年10月`），用 `history.replaceState` 不触发服务端导航；挂载时反向解析 query（`2026年` 归为年份筛选，`2026年10月`/`2026年秋` 归为周期筛选）。用户开始筛选时主动丢弃深链 hash，避免刷新后 hash 又把筛选清空、跳回旧日志
- **周期标签单一来源**：新增 `getPeriodLabel(date, mode)`，与 `getMonthStats` / `getQuarterStats` / `getYearStats` 输出格式完全一致（`2026年10月` / `2026年秋` / `2026年`），图表点击直接拿它去筛列表，避免两套口径漂移；冬季跨年处理为「12 月、1 月、2 月同属 12 月那一年」，即 1 月归到上一年

### 列表渲染与性能

- **卡片抽离并 memo**：新增 `ChangelogCard`，从页面主组件里拆出来并 `memo`。展开任意一条日志时只有该卡片重新渲染，其余卡片与右侧统计图不受影响
- **分页与自动续载**：`PAGE_SIZE = 20`，首屏只渲染最近 20 篇；底部哨兵用 `IntersectionObserver` 接近即续载，浏览器不支持时保留手动「加载更多」按钮。筛选条件变化时回到第一页
- **深链定位重写**：AI 来源的 `#changelog-<id>` 定位改用原生 `scrollIntoView`（卡片带 `scroll-mt-24` 自动扣固定导航），并在 600/1500/3000ms 补三次校正——展开正文、图片与字体加载会让目标位置在几百毫秒内反复变化。用户一旦滚轮/触摸/按键就中止校正，不与回看操作抢滚动；后台标签页切回时补一次。模块级 `activeChangelogJump` 记录当前目标，连续打开两条时上一条的延迟回调会自行失效
- **深链优先级**：目标可能不在当前筛选里或分页之后，`jumpToChangelog` 会先清空筛选、把可见条数扩到目标位置，再展开并加载正文——链接的优先级高于用户当前筛选
- **移动端总览**：新增 `MobileChangelogOverview`（`lg:hidden`），列表顶部一条可折叠摘要（总数、本月数、最新日期、前三类型），完整图表仍留在页面底部。`generatedAt` 由服务端组件传入（构建时间），不能在渲染期直接 `new Date()`：静态 HTML 是构建时生成的，用户隔月访问会在客户端算出不同月份，触发 hydration 警告

### 可读性与标签配色

- **对比度按 WCAG 计算**：新增 `getContrastTextColor`，按背景相对亮度在 `#111827` 与 `#ffffff` 之间选字色。原先类型/成就标签一律白字压在粉彩底上，白字配 `#ccff66` 的对比度只有 1.16:1，小字号几乎看不清；渐变、`rgb()/hsl()` 这类无法可靠解析的背景仍回退白色，由调用方保证底色够深
- **荣誉默认色换深蓝**：后台「添加荣誉」写入的历史默认值是亮蓝渐变（`from-blue-500 … to-blue-600`），白字在上面对比度不足。渲染时统一映射为深蓝渐变（`from-blue-700 via-blue-600 to-blue-800`），旧数据按原字符串识别后自动套用新样式，不必改数据
- **代码块修复**：`ChangelogMarkdown` 用自定义 `code` 组件渲染带样式的 `<pre>`，但 react-markdown 已输出 `<pre>`，导致 `<pre><pre>` 嵌套。现拦截默认 `pre` 直接透传子节点；判断「是否围栏代码块」也从 `language-` 前缀改为 `/(?:language-|hljs)/`，因为 rehype-highlight 会给代码块加 `hljs` 类名
- **旧日志类型重新归类**：`2026-10-22` feature→optimize、`2026-10-23` feature→fix、`2026-10-26` feature→refactor，按当天的主导变更纠正，让类型分布图恢复准确

### 墨墨日期口径收尾

- **Worker 与脚本统一**：`cloudflare/maimemo-stats` 的 `dateOf` 从「+8 小时再取日期」改为「直接取字符串前 10 位」，与 `src/utils/maimemoSync.ts` 一致；依据是「今日待学列表」实测——78 个尚未学习的记录里三个日期字段同为一天且 `finished=0`，再加 8 小时会得出「今天已学但还没学」的矛盾
- **提示词去重**：系统提示词里重复的「3. 直接转述资料的内容本身…」删掉一行，规则恢复 1~6 连续编号
- **快照重同步**：重跑 `npm run maimemo`，本地快照 `totalWords` 由 223 修正为 179、`todayNewWords` 由 104 修正为 0，并写入新的 `dailyReviews`；线上 Worker 同步部署

## 使用方式

### 筛选开发日志

1. 打开 `/changelogs`，在筛选栏点类型或年份 chip；计数会随另一维度实时变化
2. 也可以直接点右侧时间趋势图的数据点（按月/季/年）或环形图的扇区，图表就是筛选器
3. 筛选结果会写进地址栏，可直接复制链接分享，例如 `/changelogs?type=fix&period=2026年10月`
4. 移动端在列表顶部展开「日志总览」查看总数、本月篇数与类型分布

### 更新本地墨墨数据

1. 在项目根目录执行 `npm run maimemo`
2. 前台页面要等 `src/data/maimemo-stats.json` 提交并重新构建后才会更新

## 注意事项

- 「本月」统计依赖服务端传入的 `generatedAt`（构建时间）；静态导出后如果跨月不重新构建，移动端总览的「本月」仍显示构建当月，这是刻意的取舍，不要改成渲染期 `new Date()`
- AI 深链 `#changelog-<id>` 的优先级高于用户当前筛选，落地时会清空筛选并展开目标，避免「链接打开却看不到内容」
- 任何渲染日志正文的新页面都要页面级引入 `highlight.js` 主题，否则代码块只有类名没有配色
- 列表首屏只有 20 篇，`IntersectionObserver` 缺失时依赖手动按钮；深链定位靠分段校正，目标卡片若因筛选未渲染会定位失败（因此定位前先清筛选）
- 墨墨日期口径两处实现必须保持同步，改 `cloudflare/maimemo-stats` 的 `dateOf` 时别忘了 `src/utils/maimemoSync.ts`（反之亦然）
- 线上 Worker 改动需要各自 `wrangler deploy` 才生效，只改代码不部署时前台仍是旧逻辑

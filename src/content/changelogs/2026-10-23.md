## 更新概述

这一天处理两处"看起来能跑、实际边缘会坏"的地方。其一，`public/_responsive` 的变体是构建期生成且不进版本库，生成中断会留下半成品，而浏览器对 `srcset` 的优先级高于 `src`，候选返回 404 就直接破图——为此新增统一的失败兜底 Hook，缺变体时自动退回原图。其二，画廊穿插节奏原先写死为 5:4:1，图库横竖构成一变就会连续排出长串同比例图片，改为前 100 张保持固定节奏、之后按剩余真实构成推导比例。

## 主要变更

### 响应式图片加载失败兜底

- **问题成因**：`public/_responsive` 体积大且被 `.gitignore` 忽略，由 `scripts/generate-responsive-images.js` 在构建前先整体删除再逐张生成。若过程中被中断（例如启动窗口被关闭），目录里只剩半成品，而 `src/data` 下的尺寸清单仍是上一轮的，组件会继续输出指向不存在文件的 `srcset`
- **为什么必须兜底**：浏览器只要选中了 `srcset` 中的候选并拿到 404，就直接显示破图，不会自动退回 `src`。所以哪怕原图完好，缺变体也会白图
- **新增 Hook**：`useResponsiveImageFallback` 首次 `error` 时丢弃 `srcset` / `sizes`，让 `<img>` 改用 `src` 原图；同时返回 `imgKey`，失败后 key 变化会重建元素，确保浏览器真正重新发起请求
- **只回退一次**：若原图本身也 404，继续重试会陷入无限循环，因此失败即定为终态
- **补检水合前的失败**：服务端渲染的 `<img>` 在 HTML 解析阶段就开始请求，可能在水合完成前已经 404，那时 React 还没绑定 `onError`。Hook 在挂载时补检 `complete === true && naturalWidth === 0`，把这类"错过事件"的情况一并接住
- **固定档位也需兜底**：`ManifestImage` 的 `fixedVariantWidth` 模式不输出 `srcset`，但 `src` 直接指向某个变体文件，同样会 404，因此 Hook 单独接受 `hasVariant` 参数，由调用方显式告知
- **组件全面接入**：博客正文图片、文章详情、背景图、`ManifestImage`、动态九宫格与动态正文图片全部接入，缺变体时静默退回原图而不是露出破图
- **开发启动提示**：`start-dev.bat` 调整等待时间与提示语，图片变体生成期间不再过早打开页面

### 画廊穿插比例自适应

- **去掉目录名依赖**：原先按"横屏 / 竖屏 / 头像"分类目录判断图片类型，但头像目录里也可能有竖图、横屏目录里也有接近方形的图。改为统一用 `width / height` 判定：大于 1.1 为横图、小于 0.9 为竖图、其余为方图，缺宽高时按方图处理
- **前 100 张固定节奏**：`SEED_IMAGE_COUNT = 100` 保持 5:4:1 的经典穿插，保证首屏观感稳定
- **之后按真实构成推导**：每块结束后统计剩余横/竖/方的实际数量，用最大余数法在"总份数不超过 15"的范围内选择与真实比例误差最小的 `a:b:c`；每种仍有剩余的类型至少分到 1 份，避免某种图被完全挤出
- **平滑加权轮询**：按推导出的整数权重跑平滑加权轮询，交替抽取三类图片，不会出现"连排三张竖图"这种长串
- **极端比例钳制**：宽高比钳制在 0.45~4 之间。像 1200×15960 的长截图按 0.45 展示并裁切，完整图留给灯箱，避免排成 20px 宽的细条
- **表情包独立承载**：表情包固定排在最后，用更矮的方形密排行，不与普通图片混在一条节奏里

## 使用方式

### 复现与验证图片兜底

1. 临时删除 `public/_responsive` 下某篇文章的变体目录（或中断 `npm run generate:responsive`）
2. 打开该文章，图片应正常显示原图，而不是破图
3. 恢复变体后重新构建，图片重新走响应式变体

### 调整画廊节奏

1. 修改 `SEED_IMAGE_COUNT` 可改变固定节奏覆盖的图片数量
2. 修改 `SEED_WEIGHTS` 可调整前 100 张的 5:4:1 构成
3. `MAX_RATIO_PARTS` 控制自适应比例的总份数上限，数值越大穿插越平滑、块越长

## 注意事项

- 兜底只在检测到"变体存在"时生效；外链图片、SVG 等本身没有变体的图不会触发回退逻辑
- 兜底不修复缺失文件本身，只保证页面不破图；正式部署前仍应完整生成变体
- 固定档位模式（`fixedVariantWidth`）必须显式传入 `hasVariant`，否则该模式不会被兜底
- 画廊比例推导依赖清单中的 `width` / `height`，缺宽高的图会按方图参与穿插
- 极端长图在行内按 0.45 裁切展示，完整内容需点开灯箱查看

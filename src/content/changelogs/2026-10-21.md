## 更新概述

这一天把优化重点从"前端渲染开销"转向"网络往返与下载体积"。首屏上唯一阻塞解析的外链脚本改为内联，第三方连接提示改成按页面下发，统计脚本延后到页面加载完成再执行；响应式图片从博客正文扩展到 About、个人动态与 GIF，新增 `ManifestImage` 组件统一接管页面配置区的图片；首次引入 Service Worker 做运行时缓存，并在部署工作流中接入 Cloudflare HTML 缓存刷新，避免"代码已更新、用户还看到旧页面"。此外修复了切歌导致的整页白屏闪烁、移动端技能雷达塌陷、行内代码反引号外露，并把时光河流的波形生成从密集折线采样改为解析导数驱动的三次 Hermite 曲线。

## 主要变更

### 首屏网络减负

- **主题脚本内联**：`theme-init.js` 从外链同步脚本改为内联执行。它原本是全站 `<head>` 里唯一的阻塞外链脚本，任何页面首帧都要先等一次完整往返才能继续解析；脚本本体约 700 字节，内联成本远小于一次 RTT
- **连接提示按页面下发**：新增 `RouteResourceHints` 组件，Twikoo 与图床的 `preconnect` / `dns-prefetch` 不再全量挂在根布局上——文章详情页与留言板声明 Twikoo、画廊页声明图床，其余页面不再为用不到的源提前做 DNS 解析与 TLS 握手；`api.github.com` 的连接提示则直接移除，当前页面链路已不再依赖它
- **统计脚本延后**：51la SDK 的加载策略从 `afterInteractive` 改为 `lazyOnload`，在页面 `load` 完成后才加载，不再与首屏关键资源抢带宽，同时去掉多余的 `preload`
- **搜索索引不再空闲预取**：移除根布局里 `requestIdleCallback` 拉取约 40KB `/search-index.json` 的逻辑，改由导航栏搜索按钮的 hover / focus 触发；弱网设备上首屏图片与字体不再被这份索引挤占带宽
- **背景图优先级分层**：仅首页把背景图标记为 `fetchPriority="high"`（它是首页 LCP 候选），其余页面降为 `low`；同时删掉手写的背景图 `<link rel="preload">`，React 19 会依据 `<img fetchPriority srcSet>` 自动探测并下发 preload，原先是两条完全相同的 preload 重复出现
- **视频不预加载**：正文视频的 `preload` 从 `metadata` 改为 `none`，并补 `playsInline`。站内个别视频单文件达 48MB，即使只取元数据在移动数据网络下也会产生可观流量，改为用户点击播放后再下载
- **真实用户性能观测**：51la 增加 TTFB、`DOMContentLoaded`、`load`、LCP 与有效网络类型的上报，用于定位"部分设备、部分省份访问慢"的问题。指标在页面维度只采集一次，不含任何页面内容；需要关闭时设置 `NEXT_PUBLIC_DISABLE_PERF_TRACKING=true`

### 全站响应式图片

- **扫描范围扩展**：生成脚本从"博客 Markdown"扩展到三类来源——博客正文与封面、个人动态的 `images` 数组与正文、`AboutSetting.ts` 里引用的全部站内图片；扩展名增加 `gif`，动图输出保留动画的 WebP（`effort` 降到 3，控制构建耗时）
- **新增 ManifestImage 组件**：面向页面配置区（博客列表封面、About 页番剧/游戏/手风琴封面）的统一响应式图片组件，按清单构造 `srcset` 与 `width/height`；清单里没有条目（外链、SVG）时退化为普通 `<img>`
- **固定档位模式**：`fixedVariantWidth` 让门面类图片直接指向清单中指定宽度的变体、不输出 `srcset`，避免随视口或 DPR 变化换档导致糊图、闪图；指定档位缺失时退回该图最大的一档
- **补齐原尺寸档**：原图宽度在 641~1920 之间时额外生成一档原尺寸。此前 960 / 1080 宽的图只有 640 档可选，桌面端被放大后发糊，这是 About 页番剧封面模糊的主因
- **门面图单独补档**：About 页顶部三张封面固定补一档 1080 WebP，保证收起状态下稳定使用同一档
- **质量上调**：WebP 质量从 78 提高到 82，同尺寸下肉眼接近原图，体积增幅很小，避免动漫插画大面积渐变出现可见糊边
- **各页面接入**：博客列表封面、About 页番剧与游戏封面及 112px 小缩略图、个人动态九宫格与正文图片全部带上 `srcset` 与 `sizes`；九宫格原本直接拉 1MB 级原图，正文与九宫格的 GIF 换成动图 WebP 后，单张封面体积约从 2.4MB 降到 480KB

### Service Worker 运行时缓存

- **分流策略**：导航请求（HTML）走 network-first，在线一律取最新页面，离线回退到缓存页面、最后兜底缓存首页；`/_next/static/*` 与站内图片目录走 cache-first；`/search-index.json` 与 `*.xml` 走 stale-while-revalidate
- **为什么 HTML 不用 swr**：静态导出部署后，若 SW 长期返回旧 HTML，旧 HTML 引用的旧哈希分块已被删除，会出现分块加载失败；network-first 保证在线访客总是拿到新页面
- **缓存配额**：页面 30 项、静态资产 200 项、图片 300 项、数据 20 项，超出后按插入顺序删除最旧条目，图片目录列表覆盖 `_responsive`、`Blogabout`、`Momentsabout`、`aboutme`、`LTY_Picture` 等
- **跨版本清理**：`activate` 阶段删除不属于当前 `VERSION` 命名空间的所有旧缓存，并 `clients.claim()` 立即接管
- **不接管的请求**：非 GET 请求、跨域请求（51la、Twikoo、图床）、`/api/` 与 `sw.js` 本身保持浏览器默认行为
- **注册时机**：新增 `ServiceWorkerRegistrar`，仅生产构建注册，且注册挂在 `window load` 之后，不与首屏 LCP 资源竞争；开发模式不注册，并主动注销可能残留的旧注册，避免开发服务器无哈希分块被强缓存导致"改代码不生效"

### 部署后缓存刷新

- **purge 脚本**：新增 `scripts/purge-cloudflare-html.mjs`，从 sitemap 读取全站 HTML 地址，按 Cloudflare `purge_cache` 接口每 30 条一批刷新；未配置凭据或 sitemap 缺失时静默跳过，不影响部署
- **工作流接入**：`deploy.yml` 在 `deploy-pages` 之后新增一步，从线上 `sitemap.xml` 读取最新页面清单再执行 purge，并设置 `continue-on-error`
- **配置文档**：新增 `docs/cloudflare-optimization.md`，记录缓存规则分层（不可变静态资产、图片目录、`sw.js` 例外、HTML）、响应头 `immutable`、Speed 开关、purge 配置、IPv6 诊断与验证清单

### 播放器与页面交互修复

- **默认随机播放**：`MusicPlayer`、`howlerPlayerManager`、`musicPlayerPreloader` 的默认播放模式统一改为 `random`，重置状态后同样回到随机，避免界面显示与实际行为不一致
- **白屏闪烁修复**：页面淡入动画的选择器从 `html:not(.music-player-active) body` 改为 `body`。原先切歌或暂停时移除 `music-player-active` 会让选择器重新匹配，`body` 动画从 `opacity` 重新播放，整页透出白色画布
- **技能雷达塌陷**：卡片补 `min-h-[360px]`，图表容器补 `min-h-[300px]` 并给 `ResponsiveContainer` 传 `minHeight`，解决移动端单列布局下 `flex-1` 量不到高度导致图表区塌陷

### 时光河流波形重构

- **波长比例改为无理数**：副波与主波的波长比例从 `0.6` / `1.5` 改为 `1/φ`（黄金分割倒数）与 `√2`。原比例与主波的周期比是 `5:3` 与 `2:3`，公共周期只有 3 倍主波长，桌面端约每 1800px（6 张卡片）就会看到一模一样的河道
- **新增斜率函数**：`computeWaveSlope` 与 `computeWaveY` 共用同一组波长与相位，输出波形在任意横坐标处的解析导数
- **路径改为 Hermite 曲线**：`buildRiverPath` 按锚点取点，用端点解析导数生成三次贝塞尔控制点，保证曲线经过每个锚点且 C1 连续。桌面端锚点间距从 4px 放宽到 64px、移动端 48px，最大偏差约 0.10px，远小于 3px 描边宽度，路径点数减少一个数量级
- **复用主路径**：河道底部微光不再调用一次 `buildRiverPath` 生成第二份路径，改为在 JSX 中用 `<g transform>` 平移复用主路径
- **布局参数同步**：`stepSize` 更名为 `anchorStep`，卡片定位与河道路径继续共用 `computeWaveY`，保证卡片严格贴合河流起伏

### 代码块样式修复

- **选择器收窄**：强制透明背景的规则从 `.prose code`、`.prose div code` 等宽泛选择器收窄为 `.prose pre` 与 `.prose pre code`，只作用于围栏代码块，行内代码的胶囊底色不再被一并抹掉
- **去掉多余反引号**：`@tailwindcss/typography` 默认用 `::before` / `::after` 给 `code` 加反引号，而行内代码已用胶囊底色标识，反引号会以普通字符露在正文里；新增 `content: none` 规则统一去掉
- **类型引用适配**：`next-env.d.ts` 的类型引用路径改为 `.next/dev/types/*`，与开发环境生成的目录结构一致

## 使用方式

### 本地构建与预览

1. 执行 `npm run generate:responsive` 生成全站图片变体（About、动态、GIF 已包含在内）
2. 执行 `npm run build:pages` 完成静态导出，变体生成会自动进行
3. 用 `npm run serve` 预览；Service Worker 只在生产构建下注册

### 调试 Service Worker

1. 打开浏览器开发者工具的「应用 → Service Worker」，可查看 `obp-sw-v1` 的接管状态
2. 需要干净复现首次访问时，勾选「绕过网络」或先「注销」再硬刷新
3. 修改 `public/sw.js` 行为后，必须同步提升文件内的 `VERSION`，否则旧缓存会继续命中

### 配置部署后缓存刷新

1. 在 Cloudflare 创建具备「Cache Purge」权限的 API Token，记录 Zone ID
2. 在仓库 Secrets 中添加 `CLOUDFLARE_ZONE_ID` 与 `CLOUDFLARE_API_TOKEN`
3. 未配置时工作流该步骤自动跳过，不影响部署本身

## 注意事项

- 主题初始化脚本现在有两份：`layout.tsx` 内联版本与 `public/js/theme-init.js`，修改主题逻辑时必须同步，否则可能出现首屏主题与后续行为不一致
- `public/sw.js` 不能被长缓存，Cloudflare 缓存规则里需保持例外；文件内容变化但未提升 `VERSION` 时，旧缓存不会被清理
- SW 的 HTML 缓存为 network-first，离线状态下只能浏览访问过的页面；未访问过的页面离线会报错，属预期行为
- `ManifestImage` 的 `fixedVariantWidth` 依赖清单里存在对应档位，缺失时会退回该图最大的一档，不会报错但也不再固定
- `public/_responsive/` 与 `public/_changelog-content/` 都是构建产物，不纳入版本管理，部署时需随 `out/` 一起上传
- 音乐播放模式默认值为随机，但用户上次的播放状态仍保存在 `localStorage` 中并优先恢复，只有清空状态或首次访问才会看到新的默认值
- 时光河流的锚点间距（桌面 64px、移动 48px）与波形比例是配套参数，单独调整任一项都会影响曲线精度或卡片贴合度
- 静态导出仍必须使用 `npm run build:pages`，它会临时替换并恢复 Server Actions 文件

## 更新概述

这一天做了问答交互的成本优化和墨墨背单词的数据修正。问答侧新增两道零成本的短路：剥离标点后没有实际内容的问题（「？？？？」这类）不再进检索，避免标点噪音把向量检索带偏、凭空推出一堆不相关来源卡；前端对同一会话里重复提问去重，不再重复发请求。紧接着把昨天上线的答案缓存（`chat_cache` 7 天）整个移除——项目还在开发阶段，提示词和知识库随时在改，缓存会让人误以为改动没生效。

墨墨背单词则修了一批数据口径问题：一是日期字段的时区处理，二是「未开始学的新词也会带 first/last_study_date」这个坑（必须用 `last_response` 判断是否真学过，否则计划词会被算成已学），三是新增每日复习量统计，前台卡片的柱状图也相应改成「新学 + 复习」堆叠。同时把 `build` / `export` 统一指向构建包装脚本，顺手升级了 Next 与 dompurify。

## 主要变更

### 天依问答：零成本短路与去重

- **无效问题短路**：新增 `question.replace(/[\p{P}\p{S}\s]/gu, '')` 判空——只有标点、符号、空白的问题（「。。。？？」「？？？？」）直接回一句「似乎没有具体的问题呢」并返回空来源，不走向量化与检索。原因是纯标点向量化后的检索结果毫无语义，会把一堆不相关的内容推成来源卡
- **重复提问去重**：`TianyiChatPanel` 的 `ask` 在发请求前检查 `messages` 里是否已有同文本的用户消息，命中则不占位、不请求，只回一句「这个问题刚刚问过啦～往上翻翻看回答」；`useCallback` 依赖数组同步补上 `messages`
- **无资料时的回答规范**：系统提示词第 4 条从「坦白说没找到，建议换个关键词」加强为「资料不足以回答、或读者问的内容站里没有时，坦白说没找到并建议换个关键词；这种回答不要写任何【编号】引用，不要硬凑推荐」——避免模型在没内容时硬塞一个引用编号

### 移除开发阶段的答案缓存

- **表与逻辑一并删掉**：`schema.sql` 去掉 `chat_cache` 建表语句；Worker 去掉 `CHAT_CACHE_TTL_MS`、qhash 查询与 `INSERT OR REPLACE` 写入、`/admin/reindex` 的 reset 清缓存、每日 cron 的过期行回收；响应体里的 `cached` 字段也一并移除（前端本就没用）
- **流程简化**：现在是「单人限流 → 问候短路 → 无效问题短路 → 全站限流 → 向量化/检索 →（无资料则直接答）→ LLM 生成 → 返回」。全站桶仍放在两道短路之后，问候与无效问题依旧零成本、不占 200 问/天的额度
- **文档同步**：根 README 与 `cloudflare/interactions/README.md` 里「相同问题 D1 缓存 7 天」的说法改为「开发阶段不缓存答案，改动即时生效」，成本闸门仍写作三重（单人限流、全站额度、无资料不调模型）

### 墨墨背单词数据口径修正

- **未学词的识别**：墨墨对尚未开始的新词也会预置 `first_study_date` / `last_study_date`（值是该计划日的零点），仅凭日期字段会把「计划词」误算成「已学词」。改为以 `last_response` 为准——未学过的词固定为 `STUDY_RESPONSE_UNSPECIFIED`，只有真正作答过的词才计入新学、最近学习与累计已背
- **累计已背的口径**：`totalWords` 优先取真正作答过的词数（`studiedCount`），接口没给 `count` 时才退化为记录条数，避免把计划词算进总量
- **日期口径**：本地同步脚本改为直接取日期字段前 10 位（`/^(\d{4}-\d{2}-\d{2})/`）。依据是「今日待学列表」实测：78 个尚未学习的记录里三个日期字段同为一天且今日进度 `finished=0`，只有「直接取日期」能自洽（若 +8 小时会得出「今天已学但还没学」的矛盾）；同时明确不能用 `add_date` 反推，那是词书加入日期，词书迁移时会晚于首次学习
- **新增每日复习量**：首次学习日 ≠ 最近学习日即视为当天复习，聚合成 `dailyReviews`（`date -> count`），Worker 与本地脚本两侧都输出该字段，类型定义 `MaimemoStats` 补上可选 `dailyReviews`
- **卡片图表改造**：`MaimemoCard` 的柱状图从单条「新学单词」改为 `stackId="day"` 的「新学 + 复习」堆叠（新学 `#66ccff`、复习 `#b3e3ff`），横轴日期范围取两类数据的并集；汇总文案改为「近 N 天学习 X 词（新学 A · 复习 B）· 学习 N 天 · 单日最高」，最高值按新学 + 复习合计比较
- **绕过浏览器缓存**：卡片请求加 `?t=<时间戳>` 与 `cache: 'no-store'`——Worker 响应带 `Cache-Control` 会让浏览器缓存 10 分钟，刷新页面仍可能拿到旧数据；Worker 侧自己的边缘缓存保留，不会因此增加墨墨接口压力。Worker 缓存 key 版本从 `maimemo-stats-v2` 升到 `v7`，让结构变更前的旧缓存自然失效

### 构建脚本与依赖

- **构建入口统一**：`build` 与 `export` 都改为 `node scripts/build-pages.js`，删掉单独的 `prebuild` 钩子。`build-pages.js` 内部本身就会先跑响应式图片生成与开发日志正文预渲染，再执行 `next build --webpack` 并用 try/finally 恢复 actions 文件，两条命令从此走同一条路径，减少行为差异
- **依赖升级**：`next` 从 `^16.3.8` 升到 `^16.4.3`，`dompurify` 从 `^3.4.16` 升到 `^3.4.17`

## 使用方式

- 问答面板无需操作变化：重复问同一个问题会收到「刚刚问过啦」的提示；只发标点会收到「没有具体问题」的提示
- 墨墨数据同步 `npm run maimemo` 后，前台卡片会显示近 30 天「新学 / 复习」堆叠柱状图与学习天数
- 构建统一走 `npm run build`（或 `npm run build:pages`），两条命令行为一致

## 注意事项

- `schema.sql` 删掉建表语句不等于线上 `chat_cache` 表被删除：代码已不再读写它，但 D1 里仍留着一堆历史行。需要清理时手动执行 `npx wrangler d1 execute blog-interactions --remote --command "DROP TABLE IF EXISTS chat_cache"`
- 墨墨日期口径在两处实现不一致：本地同步脚本（`src/utils/maimemoSync.ts`）改为直接取日期前 10 位，`cloudflare/maimemo-stats` Worker 的 `dateOf` 仍保留 +8 小时折算（当日只改了函数名与注释，未改算法）。两边结果可能相差一天，后续应统一到实测验证过的「直接取日期」
- 系统提示词里第 3 条当日被重复插入，当前文件中存在两条内容完全相同的「3. 直接转述资料的内容本身…」，语义无影响但属冗余，后续清理
- 移除缓存后，同问题的重复提问会照常消耗 Workers AI 额度（只有单人与全站两道限流兜底），把索引重建或提示词改动后的即时生效放在优先位置是当日的取舍

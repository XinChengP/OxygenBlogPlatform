## 功能概述

修复后台管理功能无法识别前台内容的问题，并完善静态导出模式的支持，确保本地开发环境与 GitHub Pages 构建都能正常工作。

## 主要变更

### 后台管理功能修复

修复了以下后台管理功能无法识别前台内容的问题：

#### 博客文章管理
- **问题**: `blogActions.ts` 被错误替换为静态导出空实现，导致无法读取博客文章
- **修复**: 重新创建完整的 `blogActions.ts`，支持静态导出模式检测
- **功能**: 完整的博客文章 CRUD 操作、Markdown frontmatter 解析、文件系统操作

#### 图库管理
- **问题**: `galleryActions.ts` 被替换为空实现，本地图库无法显示图片
- **修复**: 重新创建完整的 `galleryActions.ts`，支持本地图片扫描和管理
- **功能**: 
  - 递归扫描 `LTY_Picture`、`Blogabout`、`Momentsabout`、`assets` 等目录
  - 支持多种图片格式（PNG、JPG、WebP、GIF、SVG）
  - 图片上传、删除、统计功能
  - 目录树结构获取

#### 动态管理、待办管理、备份管理
- **问题**: 相关的 `.real.ts` 实现文件缺失
- **修复**: 创建了完整的 actions 文件，支持双模式运行

### 静态导出模式支持

#### 构建流程优化
- **新增脚本**: `scripts/prepare-static-export.js`
  - 在 GitHub Pages 构建前自动替换 actions 文件
  - 构建完成后自动恢复原始文件
  - 支持 `prepare` 和 `restore` 两种模式

#### 双模式支持
所有 actions 文件现在都支持两种运行模式：

| 模式 | 环境变量 | 行为 |
|------|----------|------|
| 本地开发 | `NEXT_PRIVATE_STATIC_EXPORT !== 'true'` | 使用真实文件系统操作 |
| 静态导出 | `NEXT_PRIVATE_STATIC_EXPORT === 'true'` | 返回空实现或错误提示 |

#### 更新的 Actions 文件

| 文件路径 | 说明 |
|---------|------|
| `src/actions/blogActions.ts` | 博客文章管理，支持静态导出检测 |
| `src/actions/galleryActions.ts` | 本地图库管理，支持图片扫描和上传 |
| `src/actions/momentActions.ts` | 动态管理，支持 CRUD 操作 |
| `src/actions/todoActions.ts` | 待办事项管理 |
| `src/actions/backupActions.ts` | 本地备份管理 |
| `src/actions/githubActions.ts` | GitHub 推送功能 |
| `src/actions/settingsActions.ts` | 系统设置管理 |

### 构建配置更新

#### package.json
```json
"build:pages": "node scripts/prepare-static-export.js prepare && npm run sync-theme && next build && node scripts/prepare-static-export.js restore"
```

#### next.config.ts
- 添加 Turbopack resolveAlias 配置
- 支持静态导出模式的路径别名

## 技术实现

### 静态导出检测机制

所有 actions 文件顶部都包含静态导出检测：

```typescript
'use server';

// 检测是否在静态导出模式
const isStaticExport = process.env.NEXT_PRIVATE_STATIC_EXPORT === 'true' || 
                       process.env.STATIC_EXPORT === 'true';

// 根据模式返回不同实现
export async function getBlogList() {
  if (isStaticExport) {
    return []; // 静态导出模式返回空数组
  }
  // 本地开发模式使用真实文件系统操作
  // ...
}
```

### 文件替换策略

`prepare-static-export.js` 脚本的工作流程：

1. **准备阶段** (`prepare`):
   - 备份原始 actions 文件 (`.bak`)
   - 将 `index.static.ts` 的内容复制到各个 actions 文件

2. **恢复阶段** (`restore`):
   - 从备份文件恢复原始 actions 文件
   - 删除备份文件

## 注意事项

- 本地开发时所有后台管理功能（博客、动态、待办、备份、图库）均可正常使用
- GitHub Pages 构建时会自动替换 actions 文件，避免 Server Actions 不支持的问题
- 构建完成后原始文件会自动恢复，不影响本地开发
- 所有 actions 文件都包含安全检查，防止路径遍历攻击

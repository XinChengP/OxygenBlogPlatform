## 更新概述

这一天做了天依 AI 问答、博客图片排版重构和桌面端动效适配三件事。核心是「问天依」：在 Live2D 看板娘旁挂一个问答面板，读者直接用自然语言问「有没有讲 XX 的文章」，后端走 Cloudflare Workers AI + Vectorize 的 RAG 链路，把文章、动态、更新日志和站点说明检索出来再按天依口吻回答，答案里的引用编号会渲染成可点击的站内链接。

同一天围绕这条链路做了多轮迭代：先把限流的本地调试豁免从 Origin 头判断改成不可伪造的 `request.url.hostname`，堵掉一个能绕过全部额度限制的漏洞；再把全站每日额度移到问候与缓存之后，让额度消耗与真实 AI 成本对齐；接着两次修正 Qwen3 的「思考模式」开关，把输出成本压下来约六成。外围还顺手做了图片网格的任意比例支持、正文单图的默认半宽、Live2D 全局显隐开关，以及让 Electron 桌面端忽略系统的「减少动态效果」设置。

## 主要变更

### 天依 AI 问答（RAG）

- **入口设计**：看板娘控件组新增第三枚按钮「问天依」（`ask-button`，位于 `top: 125px`，与隐藏/刷新按钮同款视觉），触屏设备没有 hover 所以用 `@media (hover: none) and (pointer: coarse)` 让它常驻显示；面板打开时按钮追加 `active` 类并切文案为「收起」。面板本体用 `lazy()` 懒加载，只有首次点开才下载代码
- **知识数据源**：`scripts/index-blog.mjs` 扫描整个博客——文章（跳过 hidden）、动态（跳过 hidden）、更新日志（标题 + 提交明细）、`aiKnowledge.json`（站点功能/页面/站长说明），按段落边界切成约 700 字一块，slug 规则与 `src/utils/blogScanner.ts` 完全一致
- **检索与生成链路**：`POST /chat` → 问题向量化（`@cf/baai/bge-m3`，1024 维）→ Vectorize 检索 `blog-knowledge` → 相关度低于 0.45 视为无资料（直接回「没找到」，不调 LLM）→ `@cf/qwen/qwen3-30b-a3b-fp8` 按系统提示词生成（提示词强制模型只能用 `【编号】` 引用资料，编号之外的标题一律当幻觉处理）→ 结果写入 `chat_cache` 7 天
- **来源跳转**：新增 `aiSourceJump.ts`，来源卡指向列表页某一条时（动态、更新日志都是整页信息流），通过 `#moment-<id>` / `#changelog-<id>` 形式的 hash 滚动定位并高亮 2.6 秒；同时给 `ClientMomentsPage`、`ClientChangelogsPage`、`MaimemoCard` 的卡片补上稳定的锚点 id
- **前端渲染**：回答文本按 `【\d+】` 切分，编号映射到 `sources` 里的真实标题与链接，编号越界（模型写错序号）时降级为纯文本，不渲染悬空链接
- **索引管理**：`POST /admin/reindex`（Bearer ADMIN_TOKEN）支持分块向量化与 `deleteByIds` 清理旧向量，`vector_ids` 表登记已索引 id（因为当前 Vectorize 绑定没有 `deleteAll`）；`npm run index:blog` 一键重建

### 成本闸门与安全加固（当天多轮迭代）

- **Origin 伪造漏洞**：旧的本地调试豁免用 `Origin` 头判断 localhost，而 Origin 可被任意脚本伪造（`curl -H 'Origin: http://localhost:7120'` 就能绕过全部限流）。改为读 `request.url` 的 hostname——该 URL 由 Worker 运行时生成，线上固定是路由域名，只有 wrangler dev 才是 localhost，客户端无法伪造
- **额度与成本对齐**：全站 200 问/24 小时的桶从「流程开头」挪到「问候短路 + 缓存查询之后」，问候和缓存命中都是零 AI 成本，不再白白吃掉每日额度；单人的 8 问/小时仍留在最前面，防止单个访客刷探测
- **限流错误码区分**：`enforceBucketLimit` 支持自定义 `code/message`，个人限流返回 `rate_limited`、全站耗尽返回 `daily_limit_reached`，前端据此给出两种不同文案（「问得有点太快啦」/「今天大家问得太热情啦」）
- **检索降本**：Vectorize `topK` 从 6 降到 4——它按「查询维度」计费（topK × 1024），4 已覆盖后续最多 3 个来源的去重需求，省下约 1/3 月额度；上下文引用字数从 500 放宽到 800（metadata 本就存了 800 字，输入单价约为输出的 1/6.6，截短只是白丢块尾语义）
- **关闭 Qwen3 思考模式（两次修正）**：第一次先加 `reasoning: false` 并把 `max_tokens` 从 800 降到 300，结果该参数不被模型 schema 支持、被静默忽略，思考痕迹照旧吃掉预算，复杂问题被截在 `<think>` 内、剥离后为空，表现为「走神」。第二次改用在 user 消息末尾追加 `/no_think` 指令，实测长思考问题恢复正常，`stripThinking` 保留作兜底
- **缓存回收**：每日 cron 清理里追加 `chat_cache` 过期行物理删除——查询侧只用 `created` 过滤，回收必须靠 cron，否则表只增不减
- **截断防残缺**：答案截到 600 字后剥掉尾部可能的 `【` / `【1` 残形（`replace(/【\d*$/, '')`），避免前端渲染出悬空的引用编号；Live2D 气泡截 60 字时做同样处理
- **面板体验**：新增三条预设问题 chips（「有哪些前端开发的文章？」等），仅在还没提问时展示；请求超时从 45 秒收紧到 20 秒；消息改用自增 id 而非 index 作 key；请求失败或网络异常时把问题回填到输入框（仅在用户未输入新内容时），方便直接重试

### 博客图片排版

- **网格任意比例**：`image-grid-1-2-1`、`image-grid-4-3-3` 这类类名原先只能在 CSS 里逐条硬编码。改为在 `BlogMarkdownBase` 的 `div` 映射里用 `parseImageGridColumns` 解析类名数字，换算成 CSS 变量 `--image-grid-cols` 写进内联样式，CSS 侧只消费变量——任意段数、任意数字都通用，新增组合不必再补规则。同时修掉 `2-1-1`、`1-1-2` 旧规则把第三张图挤到下一行的问题
- **单图默认半宽**：博客正文里的单图原先把整条横幅撑满，小图被放大得很糊。新增 `article.prose img:not(.image-grid img) { width: 50% }`，用 `article` 限定作用域（留言板和 Markdown 编辑器预览同样是 `.prose`，容器却是 `div`，不该跟着变窄）；需要整行展示时给图片加 `class="image-full"` 即可，该规则用 `:not()` 把特异性抬到 `(0,3,2)` 稳压 50% 规则，不依赖两条规则在文件里的先后顺序
- **className 透传修复**：`BlogArticleImage` 此前把外部传入的 `className` 整个吞掉，导致 `image-full` 和 Markdown 语法图片的 `md-image` 标记都落不到元素上——现在合并到内置样式之后

### Live2D 全局显隐控制

- **状态管理器**：新增 `live2dVisibility.ts`，与音乐播放器的 visibility 模块同构——localStorage 持久化偏好、CustomEvent 跨组件广播；差别只在默认值（Live2D 首次访问默认显示，播放器默认隐藏）
- **双向同步**：右下角 `ScrollToTop` 的按钮组新增「隐藏/显示天依」开关（`FaceSmileIcon`，隐藏态叠加一道斜杠），与看板娘自身的隐藏按钮通过事件同步，任一侧切换另一侧立即更新
- **移动端/Electron 门控**：`Live2DDynamicLoader` 里把原来的内联 Electron 判断换成统一的 `isElectron()`，桌面端跳过触屏与「减少动态效果」限制

### Electron 桌面端动效适配

- **环境判定抽公共函数**：新增 `src/utils/isElectron.ts`，以 `typeof window.electronAPI !== 'undefined'` 为唯一依据。抽成工具函数是因为十来个组件都要用，避免各文件重复写 `window as any` 判断
- **HTML 标记**：`electron/preload.js` 在 `DOMContentLoaded` 时给 `<html>` 加 `electron` 类，便于 CSS 直接覆盖媒体查询导致的动画禁用
- **CSS 兜底**：Electron 会继承 Windows 的「关闭所有不必要的动画」设置，使 `prefers-reduced-motion: reduce` 命中、全站动画被强制禁用。`globals.css` 里对 `html.electron *` 的 `transition/animation` 统一 `revert`，并单独放行 hero 入场、导航下拉、外链守卫弹窗、首页特效等规则
- **JS 侧门控**：`homeFxEngine`、`fireworksEngine`、`typewriter`、`Footer`、`Navigation`、`TableOfContents`、`ScrollToTop`、`FriendsLink`、`RelatedLinks`、`Live2DDynamicLoader` 等处的 `prefers-reduced-motion` / `saveData` / `pointer: coarse` 判断统一改为 `!isElectron() && ...`，桌面端始终播放完整动效

### 零散调整

- **问答面板锚点定位**：更新日志默认折叠且正文按需加载，而程序化滚动不会触发悬停事件，原来的 `useAiSourceHashJump` 定位过去只看到「展开后加载正文…」。改为显式 `setExpandedLogs` + `loadChangelogHtml(id)`，并延迟 260ms 等展开布局稳定后再 `highlightAndScroll`
- **博客详情元信息**：移除文章语言（`language` 字段与 `GlobeAltIcon`）展示；元信息容器从 `flex-wrap` 改为单行 `overflow-x-auto` + 隐藏滚动条，小屏上横向滑动而不是折行
- **路由类型导入路径**：`next-env.d.ts` 中 Next 生成的路由类型路径从 `.next/types` 改为 `.next/dev/types`，适配开发环境类型结构
- **站点知识库**：`aiKnowledge.json` 修正小工具数量（站内三个 + 外部五个）、补充「学习记录」「相关链接」页面条目、更新关于页信息，保证 AI 回答与实际站点一致

## 使用方式

### 问天依

1. 打开博客任意页面，把鼠标移到右下角看板娘上
2. 点「问天依」按钮弹出问答面板（首次点击会加载面板代码）
3. 可直接输入问题，也可点一条预设问题；回答里的 `【编号】` 就是可点击的站内来源
4. 回答同时会推进 Live2D 气泡显示前 60 字，完整内容在面板内
5. 再点一次「收起」按钮或面板右上角关闭

### 重建知识索引

1. 内容增删改之后，在项目根目录执行 `npm run index:blog`
2. `ADMIN_TOKEN` 缺省从 `cloudflare/interactions/.dev.vars` 读取，也可用环境变量传入
3. 脚本重复执行安全：先按登记表清空旧向量再写入

### 图片整行展示

1. 正文单图默认占半宽
2. 需要整行时用 HTML 写法：`<img src="..." class="image-full" />`
3. 比例网格直接写类名即可，如 `<div class="image-grid image-grid-2-1-1">`，任意数字组合都支持

## 注意事项

- 问答链路依赖 Workers AI 与 Vectorize 绑定：本地 wrangler dev 的 OAuth scope 不含 Vectorize 权限时检索会失败，Worker 优雅降级为 503（前端显示「天依的大脑还没配置好」），线上运行时绑定不受影响
- Vectorize 索引维度 1024 对应 `bge-m3`，创建后不可更改；重建需 `npx wrangler vectorize create blog-knowledge --dimensions 1024 --metric cosine`
- 成本闸门共三道：单人 8 问/小时、全站 200 问/滚动 24 小时、无相关资料不调用 LLM；当天问答结果缓存 7 天，由每日 cron 回收过期行
- `isLocalDebugRequest` 只能依据 `request.url` 的 hostname，禁止改回读取 `Origin` 头——那是可被任意脚本伪造的豁免依据
- Electron 端动效放开依赖 `preload.js` 注入的 `electronAPI` 与 `<html class="electron">`，两处缺一不可
- 正文单图半宽规则用 `article.prose` 限定，留言板与 Markdown 编辑器预览不受影响；`image-grid` 内的图片也不在半宽规则范围内

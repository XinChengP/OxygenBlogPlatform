## 功能概述

修复了安全防护组件中的多个问题，包括 `fetch` API 监控的上下文绑定问题、CSP 配置导致的浏览器警告，以及完整性检测对 Next.js 运行时脚本的误报问题。

### 主要变更

#### fetch 监控修复
- **问题定位**: `NetworkMonitor.monitorFetch()` 方法中使用 `bind()` 提前绑定 `this` 上下文，在某些浏览器环境下可能导致 `fetch` 调用异常
- **修复方案**: 将 `const originalFetch = window.fetch.bind(window)` 改为 `const originalFetch = window.fetch`，并在调用时使用 `originalFetch.call(window, input, init)` 动态绑定上下文
- **一致性优化**: 保持与 `monitorXHR()` 方法的处理方式一致，统一使用 `call()` 进行上下文绑定

#### CSP 配置优化
- **问题定位**: `frame-ancestors` 指令通过 `<meta>` 标签设置时会被浏览器忽略，产生警告信息
- **修复方案**: 在 `generateCSPString()` 函数中过滤掉 `frame-ancestors` 指令，该指令只能通过 HTTP 响应头设置
- **参考文档**: [MDN - frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Security-Policy/frame-ancestors)

#### 完整性检测优化
- **问题定位**: Next.js 运行时代码（如 `self.__next_f.push`）被误报为可疑内联脚本
- **修复方案**: 添加 `allowedInlineScriptPatterns` 白名单配置，包含 Next.js 和 React 运行时脚本的匹配模式
- **白名单内容**: `self.__next_f.push`, `__NEXT_DATA__`, `next-route-announcer`, `react-root`, `react-dom` 等

### 技术实现

| 文件路径 | 说明 |
|---------|------|
| `src/components/security/HijackingProtector.tsx` | 防劫持保护组件，修复 fetch 监控的 this 绑定问题 |
| `src/utils/cspConfig.ts` | CSP 配置工具，移除 frame-ancestors 的 meta 标签输出 |
| `public/js/integrity-check.js` | 完整性检测脚本，添加 Next.js 运行时脚本白名单 |

### 影响范围

- **受影响功能**: 网络请求监控、CSP 策略应用、页面完整性检测
- **修复效果**:
  - 消除 `Failed to fetch` 错误，确保音乐配置正常加载
  - 消除 CSP `frame-ancestors` 浏览器警告
  - 消除 Next.js 运行时代码的完整性检测误报

### 注意事项

- `frame-ancestors` 指令如需使用，必须在服务器端通过 HTTP 响应头设置
- 完整性检测白名单可根据需要扩展，添加其他框架的运行时脚本模式
- 所有修复均保持向后兼容，不影响现有功能

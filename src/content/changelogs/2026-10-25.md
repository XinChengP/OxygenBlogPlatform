## 更新概述

这一天把博客从"只能看"推进到"能订阅、能统计、能分享"。新增 `/subscribe` 订阅页，聚合 RSS、Telegram 与邮件三种渠道，邮件订阅由 Cloudflare Worker + D1 承担双重确认与幂等群发；配套的互动服务同时提供文章浏览量统计、后台浏览面板与友链巡检。内容侧新增文章系列导航与 Canvas 手绘分享卡片，阅读体验上补了顶部阅读进度条、"继续阅读"提示、代码块行高亮与 PWA 安装支持，RSS 也从摘要输出升级为全文输出。

## 主要变更

### 订阅渠道

- **三种渠道聚合**：`/subscribe` 页把 RSS（站内 `/rss.xml`）、Telegram 频道、邮件订阅放在同一页；页脚同步增加订阅入口
- **邮件订阅走双重确认**：提交邮箱后 Worker 发确认信，用户点击确认才算订阅成功；`confirm` / `unsubscribe` 完成后 302 回本页并带 `?status=` 参数，页面据此展示"确认成功 / 已退订 / 链接无效"三套提示
- **开关前置到构建期**：`NEXT_PUBLIC_NEWSLETTER_ENABLED` 默认为 `false`，未配置 `RESEND_API_KEY` 时邮箱表单不展示，页面退化为 RSS + Telegram 说明页，避免用户提交后拿到 503
- **Telegram 只配入口**：新文章推送由 GitHub Actions 的 `notify.yml` 完成，站点侧只需 `NEXT_PUBLIC_TELEGRAM_CHANNEL_URL` 指向频道
- **新文章通知脚本**：检出深度为 2，用 `git diff` 只挑出本次**新增**的 `.md`（状态 A），修改既有文章、`hidden: true` 的文章一律不发通知；Telegram 优先 `sendPhoto` 带封面、失败回退纯文本；邮件走 Worker 的 `/notify`，Worker 侧按 slug 幂等；任何渠道缺 secret 就跳过并打印原因，不报错；`DRY_RUN=1` 仅打印待发内容

### 互动服务（浏览量 / 友链）

- **浏览量去重口径**：服务端按"路径 + 天 + 访客哈希"去重，访客身份为 `SHA-256(IP + User-Agent + VISITOR_SALT)`，不落原始 IP；按天去重意味着同一读者隔天再看会再计一次，这是"热度"而非"独立访客"的口径
- **限流与清理**：写接口按固定窗口限流（浏览 60 次/分钟、订阅 5 次/小时），每日 cron 清理 90 天前的去重明细，避免 D1 无限增长
- **前端零环境差异**：生产走同源 `/api/interactions/*`（由 Worker route 在静态站点之前接管），本地开发由 `next.config.ts` 的 rewrite 转发到 wrangler dev（`127.0.0.1:8787`）；Worker 未启动时前端静默降级，浏览量角标不渲染，页面其余部分不受影响
- **会话内去重**：`useArticleViews` 用 sessionStorage 记录本会话已上报的文章，首次上报拿最新总数、之后只读统计，既避免 StrictMode 重复请求，也少一次写请求
- **列表页批量统计**：博客列表用 `usePostStats` 一次请求拿全部文章的浏览量/表情计数，供卡片角标与热门榜复用
- **友链巡检**：`scripts/check-friends.ts` 逐个请求友链首页（15 秒超时，失败按离线处理），结果写入 `public/friends-status.json`；`FriendsLink` 据此在卡片上显示在线状态点。巡检在每次部署前与每周定时各跑一次
- **后台浏览面板**：`ViewsPanel` 读取 Worker 的 `/admin/stats`（Bearer `ADMIN_TOKEN`），展示总浏览量、订阅数与分页排行。本地开发经 `next.config.ts` 的 `/api/admin-stats` 代理直连线上服务——本地 wrangler dev 既没有线上 D1 数据也没有 secrets，直接转发看不到真实数据

### 系列导航与分享卡片

- **系列字段**：博客 frontmatter 新增 `series` 与 `seriesOrder`，`blogScanner` 一并读取；相同 `series` 的文章在详情页聚合成系列，未给 `seriesOrder` 时按发布日期排序
- **系列进度条**：放在元信息栏下方、正文开始之前——阅读决策发生在正文之前（"这是第几篇？要不要先读第一篇？"），而大纲面板多数屏幕默认收起、移动端藏在抽屉里，作为系列入口可见性太差。默认一行紧凑条（系列名 + `2/5` 进度 + 前后篇跳转），完整目录收起，点"全部 N 篇"才展开
- **分享卡片**：用 Canvas 手绘 3:4 竖版海报（逻辑尺寸 900×1200，导出 2 倍采样保证清晰），天依蓝渐变底 + 白色卡片 + 封面/标题/摘要/日期 + 品牌信息与文章二维码。不引入 `html2canvas` 这类重依赖，布局固定所以纯 Canvas 可控性最好、体积也最小
- **二维码不污染画布**：二维码用 `qrcode.react` 的 `QRCodeCanvas` 渲染成真 `<canvas>` 再 `drawImage` 到海报上，同文档 canvas 不会污染画布
- **封面跨域降级**：封面来自第三方图床时用 `crossOrigin='anonymous'`，需服务端 CORS 放行才能导出；加载失败或导出被污染时降级为无封面/提示截图，绝不阻塞弹窗
- **上线时间统一**：页脚"已陪你走下去"的运行时间改由 `FooterSetting.ts` 的 `siteLaunchDate` 统一提供，避免多处各写一份起始时间

### 代码块行高亮与 PWA

- **行高亮**：围栏代码块的 meta 支持 `hl=` 标记（如 `js hl=3,5-7`），由 `ServerBlogMarkdown` 解析成行号数组，`CollapsibleCodeBlock` 在 `wrapLines` 模式下按行号注入背景样式；折叠态只渲染前 30 行，高亮集合照常生效
- **PWA 配置**：新增 `public/manifest.webmanifest`（名称、主题色 `#66ccff`、`standalone`、192/512 图标与 maskable 图标），`layout.tsx` 挂载 manifest 并补齐 `icon-192`、`apple-touch-icon`；图标由 `scripts/generate-pwa-icons.mjs` 从站点头像生成，与 manifest 保持一致
- **离线能力复用**：PWA 安装后复用的仍是 `public/sw.js` 已有的运行时缓存，不额外引入新的缓存层

### 阅读进度

- **只存百分比**：`readingProgress.ts` 每篇只存 0-100 的整数百分比，不存正文偏移，布局变化后也能恢复到相近位置
- **有效区间**：3% 以下等于刚打开、92% 以上基本读完，都不记录也不提示；记录超过 30 天视为过期
- **容量控制**：超过 50 条时按时间戳淘汰最旧记录，长期使用不会让 localStorage 无限膨胀
- **顶部进度条**：用 `requestAnimationFrame` 节流，只在数值变化时才 `setState`，避免滚动时高频更新触发"Maximum update depth exceeded"
- **落盘节流**：进度每变化 2 个百分点才写一次 localStorage
- **继续阅读提示**：挂载后读到有效历史进度且本会话未关闭过时，延迟 1.5 秒在底部中央浮出"上次读到 N%"；关闭状态只记在 sessionStorage，阅读记录本身不受影响

### 其他调整

- **RSS 全文输出**：新增 `content:encoded` 输出全文，保留摘要作为兼容回退；全文 HTML 会剥离 `<style>` / `<script>` 与内联事件属性（文章自定义 CSS 会污染订阅器布局，脚本则毫无用处），协议相对地址（如 B 站播放器的 `//player.bilibili.com/...`）补全为 `https://`，站内相对路径补全为绝对地址并兼容子路径部署
- **装饰图排除灯箱**：正文装饰性图片（聊天头像、表情包等）加 `data-no-lightbox` 后不进入灯箱列表、不响应点击放大，也不再输出 `role="button"` / `tabIndex` / `aria-label`，避免键盘 Tab 与读屏把纯装饰图当成可操作按钮；仍保留 `getAssetPath` 补前缀与响应式变体能力
- **代码块水合修复**：`ThemeAwareCodeBlock` 首帧固定使用与服务端一致的亮色高亮主题，挂载完成后再按 `resolvedTheme` 切换。`next-themes` 在客户端首次渲染时会同步读取 localStorage，若直接使用 `resolvedTheme`，暗色访客的服务端 HTML 与首帧内联样式不一致，会触发 hydration mismatch
- **类型引用路径**：`next-env.d.ts` 的类型引用同步到 `.next/dev/types/*`，与开发环境生成的目录结构一致

## 使用方式

### 开启订阅渠道

1. Telegram：在仓库 Secrets 配置 `TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID`，构建时设置 `NEXT_PUBLIC_TELEGRAM_CHANNEL_URL`
2. 邮件：部署 `cloudflare/interactions`（D1 建表 + `RESEND_API_KEY` + `ADMIN_TOKEN`），构建时设 `NEXT_PUBLIC_NEWSLETTER_ENABLED=true`
3. 本地联调：`wrangler dev` 起在 8787 端口，Next dev 会自动转发 `/api/interactions/*`；未启动时页面静默降级

### 验证浏览量统计

1. 打开任意文章详情页，元信息栏应出现浏览量角标
2. 同一会话内重复刷新不重复上报（sessionStorage 去重），换浏览器或隔天会重新计数
3. 后台仪表盘填入 `ADMIN_TOKEN` 可查看总量与分页排行

### 生成分享卡片

1. 文章页点分享 → 选择"生成分享卡片"
2. 等待海报绘制完成，点下载保存 PNG 或长按/右键保存
3. 封面非本站域名时若导出失败，会提示截图保存

### 编辑代码块行高亮

在围栏代码块信息串中追加 `hl=` 标记，例如：

````markdown
```js hl=3,5-7
```
````

### 记录文章系列

在文章 frontmatter 中加 `series` 与可选 `seriesOrder`：

```yaml
series: "从零搭建博客"
seriesOrder: 2
```

## 注意事项

- `NEXT_PUBLIC_NEWSLETTER_ENABLED`、`NEXT_PUBLIC_TELEGRAM_CHANNEL_URL` 都是构建期内联变量，改动后必须重新构建部署
- 互动服务未部署或超时（8 秒）时，浏览量角标、订阅表单等会静默降级，不影响页面其余部分
- 后台浏览量面板的 Token 存 localStorage 仅作本地便利，真正的鉴权在 Worker；后台本身已被 `AdminGuard` 限制在生产环境之外
- 新文章通知只看 git 中状态为 A 的新增文件，改名、复制或修改既有文章都不会触发通知
- 分享卡片的二维码必须是可公开访问的绝对地址，站内子路径部署时会自动带上 basePath
- 阅读进度按百分比恢复，若文章结构大幅改动，恢复位置只会"接近"而非精确
- `data-no-lightbox` 依赖 `rehype-sanitize` 的 `*` 规则放行 `data*` 属性，修改清洗规则时不要收紧该项
- PWA 安装复用 `sw.js` 的运行时缓存，HTML 仍为 network-first，离线只能浏览访问过的页面

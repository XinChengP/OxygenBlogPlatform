## 更新概述

这一天把待办事项从「本地 JSON 文件」整体搬到云端：新增一个部署在 Cloudflare 上的任务清单同步服务（tasks 表）作为唯一权威数据源，博客侧只负责读取与展示；本地 `src/content/todo.json` 被删除，换成只读快照 `src/data/todoSnapshot.json`，仅在构建机访问不到同步 API 时兜底。

之所以要动这一层，是因为原来的待办数据写死在仓库里的 JSON 文件中——手机端想加一条待办，只能回到电脑改文件、提交、等 CI 重新构建；而新的同步服务本身已经支撑 Windows / Android 双端的任务清单应用，字段级增量同步（Last-Write-Wins）天然支持多端并发编辑。顺带把待办的排序、逾期判断、日期格式化抽成共用工具，并修掉了导航下拉菜单「鼠标稍微一抖就消失」的老问题。

## 主要变更

### 数据源与读取链路

- **唯一权威数据源**：待办数据以线上同步 API 的 `tasks` 表为准，远端字段语义为 `content ↔ title`、`notes ↔ notes`、`dueDate ↔ due_at`、`remindAt ↔ remind_at`、`completed ↔ completed_at`、`priority ↔ priority(0-3)`
- **三级读取兜底**：新增 `loadTodoConfig()`，读取顺序为「线上 API → 本地只读快照 → 空列表」。成功拉取的结果在进程内缓存 60 秒，避免开发环境每次刷新都打接口；接口失败时回退快照并附带可读的中文失败原因，页面永远有数据可渲染
- **只读快照的定位**：`src/data/todoSnapshot.json` 纳入版本管理，只用于 CI 构建兜底；只有后台「同步」动作成功之后才会重写快照，普通编辑操作不再落任何本地待办文件，避免出现「本地文件与云端不一致」的双写问题
- **原子写快照**：先写 `.tmp` 临时文件再 `rename`，中断不会留下半截 JSON；同一进程内的快照写入用模块级 Promise 链串行化，防止并发覆盖

### 同步客户端

- **端点轮换与重试**：主地址 `https://todoapi.xinchengp.cn` 之外，预置 `2053 / 2083 / 2087 / 2096 / 8443` 五个备用端口——国内直连 Cloudflare 的可达性按时段波动，443 劣化时备用端口仍可能通；全部端点最多轮询 2 轮
- **时间预算**：单请求超时 15 秒，单次同步总预算 20 秒，避免构建期或后台操作被网络问题拖死
- **鉴权与环境变量**：`Authorization: Bearer <TODO_SYNC_TOKEN>`；未配置令牌时直接返回可读原因（提示在 `.env.local` 或 GitHub Secrets 中填写），不会发起无意义的请求
- **分批推送**：服务器单次上限 500 行，客户端按 200 行分批，留出余量
- **静态导出兼容**：构建期请求使用 `force-cache`，`no-store` 会让 Next 把路由判定为动态渲染，与 `output: 'export'` 冲突；开发/运行时仍用 `no-store` 保证实时性

### 写入 Action 重构

- **直接推送远端**：新增/修改/删除/切换完成状态全部走推送接口，并采用服务器裁决后返回的最终行刷新界面，而不是乐观地相信本地状态
- **单调递增写入时间戳**：远端采用字段级 LWW，同一毫秒内连续写同一字段时服务器按「平局服务器赢」会丢弃后一次。新增进程内 `nextWriteTimestamp()`，保证本进程产生的 `at` 严格递增，规避快速连点导致的丢写
- **静态导出全部禁用**：所有写操作在静态导出模式下统一返回「静态导出模式不支持此功能」，避免构建期引入 Node 文件系统与网络写操作
- **配置项拆分**：标题与「是否显示统计」这两个远端没有的字段，单独保存在快照里，由 `updateTodoConfigSettings` 维护

### 展示层统一

- **共用工具 `todoDisplay.ts`**：排序规则统一为「未完成 → 优先级 → 截止日期 → 创建时间」；逾期判断按北京时间的「今天」比较，与 `due_at` 的换算口径一致；截止日期直接按 `YYYY-MM-DD` 字符串格式化，绕开 `new Date('YYYY-MM-DD')` 按 UTC 解析导致的负时区少一天问题
- **侧栏卡片增强**：`TodoWidget` 新增备注（最多两行）、提醒时间、逾期红色标记，底部统计从「还剩 N 项」升级为「还剩 N 项，其中 M 项已逾期」
- **仪表盘统计切换**：后台首页的待办完成进度改走 `loadTodoConfig()`，不再直接读 `todo.json`

### 构建与导航

- **构建期固化**：动态页面改为 `async` 组件并显式声明 `dynamic = 'force-static'`，构建时把线上待办拉取一次、渲染进静态 HTML，前台访问不产生额外请求
- **CI 注入**：`deploy.yml` 注入 `TODO_SYNC_TOKEN` 与 `TODO_SYNC_ENDPOINT`；未配置 secret 时构建期自动回退到仓库内的只读快照，不影响部署
- **下拉菜单防误关**：导航下拉菜单的悬停收起从「立即关闭」改为 260ms 延迟关闭，并用 `padding` 代替 `margin` 补齐按钮与面板之间的间隙——原来这段间隙不属于下拉容器，鼠标从按钮移向面板时会触发 `mouseleave`，菜单瞬间消失。同时补了定时器清理，避免组件卸载后仍触发 `setState`；导航栏顶部透明时下拉面板也跟随透明并使用白字，滚动后同步切换为毛玻璃
- **工具收录**：小工具页新增「任务清单（Windows / Android）」外部入口，指向这套同步服务的客户端仓库

## 使用方式

### 查看与编辑待办

1. 动态页 `/moments` 侧边栏展示待办，数据来自线上同步 API（构建期拉取）
2. 本地开发环境访问 `/admin/todo` 进行增删改，操作会实时推送云端并刷新缓存
3. 后台点「同步」可强制全量拉取一次远端数据，并同时更新仓库内的只读快照

### 配置同步令牌

1. 在 `.env.local` 中新增 `TODO_SYNC_TOKEN=你的同步令牌`
2. 如需自定义端点，再补 `TODO_SYNC_ENDPOINT` 与可选的 `TODO_SYNC_FALLBACKS`（逗号分隔）
3. GitHub 仓库的 Secrets 中同样配置 `TODO_SYNC_TOKEN`，否则 CI 构建会回退到快照数据

## 注意事项

- 本地 `todo.json` 已删除，唯一数据源是线上同步 API；请勿再手工新增本地待办文件
- 快照只读、仅供兜底，普通编辑不写快照，只有后台「同步」动作会更新它
- 静态导出模式下所有待办写操作均不可用，返回「静态导出模式不支持此功能」
- 截止日期统一按北京时间零点换算为毫秒时间戳，跨时区构建不会出现「截止日期少一天」
- 远端同一毫秒的重复写入会因「平局服务器赢」被丢弃，已用单调递增时间戳规避；其它客户端（如手机 App）直接并发写同一字段仍可能覆盖，这是 LWW 协议本身的取舍
- 未配置 `TODO_SYNC_TOKEN` 时页面不会空白，但数据停留在快照时刻

## 更新概述

这一天做了两件相互关联的事：给墨墨背单词数据接口加上 D1 持久化与兜底，以及把学习打卡页从「一堆独立卡片」整合成「今日概览 + 学习数据面板 + 学习记录」三段式布局。

前者的动机很直接：墨墨的 `query_study_records` 单次最多返回 1000 条且没有 offset，只能按 `next_study_date` 时间窗分页。词量一旦超过 1000，单次请求就会被截断，历史每日新学/复习统计随之失真——之前「累计已背 179 个」这类数字其实是残缺数据算出来的。现在 Worker 侧每天做一次全量回填（时间窗二分递归），把每天的新学/复习数写进 D1，之后的统计直接从库里读，已采集的历史不会再丢。

## 主要变更

### D1 持久化与全量回填

- **两张表各司其职**：`maimemo_daily` 一天一行，记录当天新学与复习词数；`maimemo_meta` 固定一行，存最新一次结果的 JSON 快照与上次回填时间。表不需要手动建，Worker 首次请求会执行 `CREATE TABLE IF NOT EXISTS`，也可以手动跑 `schema.sql`
- **时间窗二分递归**：`query_study_records` 没有 offset，只能按 `next_study_date` 切窗口。先发一次 `as_count` 数量探测，数量超过单页上限 1000 就把窗口对半切开递归拉取，最大深度 3，避免请求数失控
- **回填节流**：历史全量回填 24 小时内最多做一次（分页请求较多，容易触发墨墨频控）；日常刷新只拉最近 30 天记录，用于「最近学习单词」与今日新学的记录口径兜底
- **只增不减**：写入用 `MAX(旧值, 新值)`，数据只会因补全而变大，不会因为某次只拉到部分记录而变小
- **快照复用与兜底**：D1 快照 10 分钟内直接复用，避免频繁消耗墨墨额度；上游接口全部失败时用快照返回，页面不会突然空掉。D1 未绑定时 Worker 自动降级为「无持久化」模式，逻辑与旧版一致，本地 `wrangler dev` 也能正常调试

### 统计口径修正

- **今日新学改用 `get_today_items`**：按 `is_new: true` 且已完成过滤，比「从全量记录按首次学习日期反推」更准；接口不可用时才回退记录聚合
- **待复习与顽固词改为精确计数**：待复习用 `as_count` + `next_study_date` 条件计数，顽固词用 `tags: "STICKING"` + `as_count`，都不再是「在最近 1000 条里估算」
- **未学的词不再计入**：墨墨会给「仅加入计划、尚未学习」的新词预置 first/last_study_date，唯一可靠的区分依据是 `last_response`——未学过固定为 `STUDY_RESPONSE_UNSPECIFIED`。只有真正作答过的词才计入新学、最近学习与累计已背
- **tags 类型双兼容**：官方 OpenAPI 把 `StudyRecord.tags` 标为字符串，线上实际返回字符串数组，两种形态都兼容，避免接口纠正类型后顽固词静默归零
- **频控单独报错**：上游 429 单独映射为 `upstream_rate_limited`（提示「触发频控，请稍后重试」），不再混在通用错误里
- **时区统一**：Worker 运行在 UTC，日期换算统一按北京时间；`dateOf` 取日期字段前 10 位即学习日，与本地同步脚本保持一致

### 本地同步脚本对齐

- **同一套分页策略**：`src/utils/maimemoSync.ts` 同步实现时间窗二分与 `as_count` 精确计数，并改用 `get_today_items` 取今日新学
- **`localDate` 按北京时间**：改用 UTC+8 偏移后再取年月日，避免 CI 在 UTC 时区把日期算错一天
- **错误提示细化**：新增 429 频控提示；Token 失效时明确提示到墨墨 App「开放 API」页面重新生成

### 学习打卡页整合

- **三段式布局**：原来「统计卡片 + 热力图 + 科目分布 + 趋势 + 墨墨卡片」五块各自带边框，视觉零碎；现在合并为「今日概览」一张横向卡、「学习数据」一张大卡（内部用分隔线分区：热力图 / 近 30 天趋势 + 科目分布 / 英语背单词）、以及学习记录列表
- **今日概览横向化**：左侧今日状态（已打卡显示时长与科目 chip，未打卡显示火苗提醒），右侧四项累计统计并排，桌面端用竖线分隔、移动端上下堆叠。首帧客户端日期未就绪时显示「读取中…」，避免水合瞬间误报「还没打卡」
- **热力图铺满**：默认展示周数从 26 周改为 52 周（覆盖完整一年），所有周列共用同一套网格模板，宽屏按 `1fr` 均分铺满整行、格子随列宽放大，窄屏保底 12px 并横向滚动
- **趋势图改柱状**：打卡数据稀疏、常有大量 0 值天，折线在两个点之间几乎不可见；改用柱状图并限制最大柱宽，能直观看出「哪天学了、学了多久」
- **墨墨卡片嵌入模式**：新增 `embedded` 属性，嵌入时不再自带外框与上边距，作为「学习数据」面板的第四个子区块渲染；没有打卡记录时仍以独立卡片兜底展示墨墨数据
- **科目分布补日均**：底部增加「日均学习」汇总行，科目较少时也能撑起区块高度，同时补充统计信息；移动端数字与单位加 `whitespace-nowrap`，避免「小时」被拆到下一行

## 使用方式

### 部署墨墨数据接口

1. `cd cloudflare/maimemo-stats && npm install`
2. `npx wrangler d1 create blog-maimemo --location apac`，把输出的 database_id 填进 `wrangler.toml`（区域创建后不可更改）
3. `npx wrangler secret put MAIMEMO_API_TOKEN` 写入墨墨 Token
4. `npx wrangler deploy`，访问 `https://blog.xinchengp.cn/api/maimemo/stats` 能看到 JSON 即成功

### 更新构建期快照

1. 在项目根目录执行 `npm run maimemo`
2. 提交 `src/data/maimemo-stats.json` 后可让构建期数据与线上一致（前台页面本身会优先在运行时拉接口）

## 注意事项

- 线上 Worker 改动必须各自 `wrangler deploy` 才生效，只改代码不部署时前台仍是旧逻辑
- D1 的 `database_id` 已固定为 apac 区域，创建后不可更改；想关掉持久化可整段注释 `[[d1_databases]]`，Worker 会自动降级
- 历史全量回填每天最多一次，避免触发墨墨频控；遇到 429 时接口返回 `upstream_rate_limited`，稍后重试即可
- Worker 与 `src/utils/maimemoSync.ts` 两处必须保持同一套日期与分页口径，改其中一处时别忘了另一处
- 「仅加入计划、尚未学习」的词同样带 first/last_study_date，只能用 `last_response` 区分，不要用日期字段推算是否学过
- 快照有 10 分钟新鲜度窗口，前台数据最多延迟 10 分钟，这是为节省墨墨额度刻意保留的取舍

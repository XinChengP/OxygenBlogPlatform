## 更新概述

当天两件事。一是后台仪表盘从简单的饼图卡片重构为带全宽数据概览条、Recharts 时间趋势图和分类分布图的完整概览页；同时 AdminLayout 重构出 `PAGE_META` 路由表，顶栏标题和图标随当前路径自动匹配。为解决本地开发跨域和数据来源问题，`next.config.ts` 新增 `/api/admin-stats` 代理到线上互动服务，Worker 的 `withCors` 也补上了缺失的 CORS 头。二是把 `AnimatedNumber` 的收尾帧从"永远小 1"的 floor 逻辑改成直接落目标值。

## 主要变更

### 后台仪表盘重构

#### DashboardClient 大改

- **数字动画组件 AnimatedNumber**：从原来散落在各处的 `useEffect` 改为独立的封装组件。缓动函数是 `easeOutExpo`（`1 - 2^(-10t)`），配合 `requestAnimationFrame` 60fps 帧驱动
- **数据概览条**：顶部新增全宽统计条，按 2/3/5 列响应式网格排布，每个统计项一张卡片（带图标 + 渐变色底 + 数字动画），覆盖文章总数/字数、动态总数/字数、日志总数/字数；引入 `StatOverviewCard`（计数型）与 `TrendCard`（带趋势箭头，对比上月数据）两种卡片，后者在月初会显示"相比上月"的升降
- **时间趋势图表**：Recharts 折线图，按月份展示文章/动态/日志发布量的时间轨迹；图表容器补了 `min-h-[300px]`，避免移动端折叠
- **分类分布饼图**：`CategoryPieChart` 卡片顶部标题改成渐变色文字 + 20 秒匀速旋转的分类图标（Framer Motion `animate rotate:360`），卡片整体新增入场动画（`AnimatePresence` + `motion.div`）
- **响应式设计**：整个 Dashboard 用 `motion.div` 包裹，按条目分 `initial="hidden" / animate="visible"` 做渐入，移动端单列、桌面端多列栅格
- **欢迎栏简化**：去掉原来悬浮的 sticky 背景栏，改为 flex 行布局，日期胶囊移到右侧自适应对齐

#### AdminLayout 重构

- **PAGE_META 路由表**：新增 `PAGE_META` 常量数组，顺序按路径长度从长到短排列（`/admin/blogs/edit` → `/admin/blogs` → `/admin`），前缀匹配时优先命中最具体的子页面。每一项声明 `prefix`、页面中文标题、Lucide 图标组件
- **页面标题/图标自动匹配**：AdminLayout 用 `usePathname()` 取当前路由，从 `PAGE_META` 中找到第一条 `pathname.startsWith(prefix)` 的记录，把其中的 label 和 icon 注入顶栏；找不到就回退到「管理后台」
- **路由覆盖**：涵盖了所有新增/已存在的管理路由：文章/动态/日志/图床（本地/远程/管理器）/学习打卡/待办/备份/设置/仪表盘

#### Cloudflare Worker 修复

- **`withCors` 头缺失**：互动服务 Worker 之前只给部分响应（如浏览量接口）补了 CORS 头，其他路由（后台统计 `/admin/stats`、订阅等）返回时缺 `Access-Control-Allow-Origin`。本地后台仪表盘跨域直连线上 Worker 时，预检 OPTIONS 通过、实际响应却没 CORS 头，浏览器拦截报 `Failed to fetch`
- **修复**：新增 `corsHeaders(request)` 工具函数，按 `request.headers.get('Origin')` 匹配 `ALLOWED_ORIGINS`（`blog.xinchengp.cn`、`localhost:7120`、`127.0.0.1:7120`），返回统一 CORS 头；`handle` 里的每一处 return 前都调用 `withCors` 包一层，不再各自单独处理

#### 本地开发代理

- **问题**：后台仪表盘 `/admin/stats` 是跨域请求，线上 Worker 缺 CORS 头时浏览器拦截；而本地 wrangler dev 没有 D1 线上数据也没有 secrets（`ADMIN_TOKEN`），就算转发到本地 Worker 也看不到真实数据
- **方案**：`next.config.ts` 新增 `/api/admin-stats` rewrite，目标为 `https://blog.xinchengp.cn/api/interactions/admin/stats`。浏览器侧始终是同源请求（路径是 `/api/admin-stats`），不触发 CORS 预检、不受 CSP `connect-src` 约束；本地 dev server 作为反向代理把请求原样转给线上 Worker，返回真实 D1 数据和 secrets 签名
- **后端鉴权仍在 Worker**：Token 验证（`Bearer ADMIN_TOKEN`）由线上 Worker 负责，`next.config` 的 rewrite 只是路由转发、不做任何鉴权旁路；静态导出产物没有 `/api/admin-stats` 路由，生产环境后台本身已被 `AdminGuard` 拦截，不存在暴露风险

#### 图表组件适配

- **TimeStatsChart / TypeStatsChart**：调整容器高度和 `ResponsiveContainer` 的 `minHeight`，适配后台布局宽度；Recharts 的 X 轴时间刻度用中文本地化

### 数字动画收尾修复

- **问题**：`AnimatedNumber` 的 `easeOutExpo` 在 progress=1 时等于 `1 - 2^(-10)` ≈ 0.99902，永远不等于 1。结束帧用 `Math.floor(0.99902 × value)` 比真实值小 1，导致仪表盘统计数字（例如文章总数 128）动画最终停在 127，与图表总计不一致
- **修复**：加一个边界判断——`progress >= 1 ? value : Math.floor(easeOutExpo × value)`，动画完成帧直接落到目标值，避开 floor 的"永远小 1"陷阱

## 使用方式

### 后台仪表盘数据来源

1. 确保线上互动服务 Worker 已部署并配置好 D1、`ADMIN_TOKEN`
2. 本地开发 `npm run dev`，后台仪表盘自动经 `/api/admin-stats` 代理拿线上数据
3. 后台仪表盘「浏览量面板」填入相同的 `ADMIN_TOKEN`，也能看分页排行

### 新管理路由自动展示

后台新增管理页时：
1. 在 `AdminSidebar.tsx` 加入口
2. 在 `PAGE_META` 数组中加 `{ prefix: '/admin/xxx', label: '中文标题', icon: 对应图标 }`
3. 顺序按路径长度从长到短排列，保证 edit 子页面能命中更具体的图标/标题

### 开发环境访问线上 D1 数据

1. 浏览器打开 localhost:7120，后台仪表盘的 `/api/admin-stats` 同源请求被 dev server rewrite 到线上 Worker
2. Worker 校验 `ADMIN_TOKEN` 后返回真实数据；本地 wrangler dev 没有线上 D1 数据，这条路走不通

## 注意事项

- `/api/admin-stats` rewrite 只在 Next dev 配置里生效（next.config.ts 的开发配置块），静态导出产物没有该路由；生产后台已被 AdminGuard 拦截，不存在暴露风险
- Token `ADMIN_TOKEN` 需同时在 Worker secrets 和 ViewsPanel 的 localStorage 里配置；不同步时后台面板会返回 401
- PAGE_META 的 prefix 匹配顺序敏感：`/admin/blogs/edit` 必须排在 `/admin/blogs` 之前，否则编辑页会被文章管理的图标/标题抢占
- 数字动画收尾修复用 `progress >= 1 ? value : ...`，如果未来把缓动函数换成没有"终点偏差"的曲线（如线性），这个判断不会出错，仍可保留
- Dashboard 的趋势对比逻辑依赖上月数据（首次部署时没有上月基线，TrendCard 会显示 0），属预期行为

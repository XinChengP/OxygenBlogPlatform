## 更新概述

一次覆盖面较广的重构与性能优化：搜索弹窗改为按需加载并预取索引，音乐播放器拆分组件并全面优化交互性能，博客目录改为服务端提取，画廊列表改为缩略图 + 轻量卡片渲染消除进入页面卡顿，同时统一全站层级令牌、滚动锁与响应头配置；并一并加固静态导出构建流程与 Token、CSP 存储安全策略。

## 主要变更

### 搜索弹窗按需加载

- **按需加载**：搜索弹窗依赖 fuse.js 与 framer-motion，原先直接挂在根布局，导致所有页面首屏都要下载这部分代码；改为新增 `LazySearchDialog` 包装，只在用户第一次唤起搜索（点击搜索入口或按 Ctrl/Cmd + K）时才动态加载真正的弹窗组件
- **竞态处理**：懒加载期间「打开」事件可能先于弹窗挂载发出，用 `searchEvents` 的模块级标记记录打开意图，弹窗挂载后再消费，避免首次点击无效
- **索引缓存与去重**：`searchIndex` 做模块级缓存 + 请求去重，`search-index.json` 全站只请求一次
- **空闲预取**：浏览器空闲时（`requestIdleCallback`，超时 4 秒；不支持则降级为 3 秒定时器）提前预取索引，首次打开无需等待下载

### 音乐播放器重构

- **组件拆分**：从单文件拆出独立且带 memo 的 `ArtistName` / `PlaylistPanel` / `ProgressBar` / `VolumeSlider`，避免播放进度每 250ms 更新时连带重算无关内容
- **进度条交互**：拖动期间只更新预览位置，抬手（pointerup）才真正 seek——旧实现每次 mousemove 都调用 seek，快速拖动会触发大量音频 Range 请求与解码抖动；预览位置用 requestAnimationFrame 节流，不再让指针事件频率直接触发重渲染
- **指针与触摸统一**：统一使用 Pointer Events，并设置 `touch-action: none`，移动端拖动进度条时页面不会跟着滚动
- **键盘支持**：方向键 ±5 秒、PageUp/PageDown ±30 秒、Home/End 跳转
- **歌单虚拟列表**：固定行高 56px 加 5 行缓冲区，只渲染可视区域，长歌单滚动不再卡顿
- **稳定歌曲标识**：新增 `songKey`（歌名 + 歌手 + 来源），在线歌单 834 首且顺序可能调整，只存索引会在下次加载时恢复到错误的歌曲
- **歌手颜色高亮**：按名称长度降序匹配避免短名抢先命中，洛天依 #66ccff、乐正绫 #ee0000、言和 #00ffcc，星尘单独处理为双色
- **网易云接口调整**：Meting API 主用 `api.qijieya.cn`（playlist 接口返回完整歌单），备用 `api.injahow.cn`（有服务端缓存、可能少歌），CSP 与图片域名白名单同步登记
- **封面改 webp**：音乐封面批量转 webp，体积显著下降

### 博客目录服务端提取

- **构建期提取**：新增 `tocUtils.extractHeadings`，在服务端调用一次把目录作为纯数据传给客户端目录组件，避免为了生成目录再把整篇正文随 RSC 数据发到浏览器
- **准确性处理**：先剔除围栏代码块、去掉行内标记，标题 id 规则与正文标题保持一致，重复标题按同一规则编号

### 层级与滚动体系

- **层级令牌**：新增 `zIndex.ts` 统一排序——页面内容 < 装饰/浮动控件 < 导航 < 模态弹层 < 轻提示，修复导航栏盖住搜索弹窗、播放器盖住模态层等魔数值混乱问题
- **滚动锁**：新增 `useBodyScrollLock`，引用计数保证多个弹层叠加时不会提前解锁，并补偿滚动条宽度避免桌面端内容横向跳动
- **其他精简**：`ScrollToTop` 与 `Lantern` 大幅精简，新增烟花引擎，滚动管理与主题切换动画一并优化

### 响应头与可访问性

- **响应头配置**：新增 `public/_headers`，静态资源长缓存（immutable）、其余资源强制校验，并补齐 HSTS、X-Frame-Options、Referrer-Policy、Permissions-Policy、X-Content-Type-Options 等安全头
- **同页链接修复**：`smooth-navigation.js` 对同页链接（含仅查询参数变化）不再添加过渡类，避免页面一直保持半透明
- **标题恢复修复**：`dynamic-title.js` 改为记录「离开瞬间」的标题，而非脚本加载时的初始标题，返回页面后标题能正确还原
- **可访问性**：修复画廊、博客配图、动态图片网格的点击与键盘交互可用性

### 构建与部署

- **部署流程**：`deploy.yml` 增加 README/LICENSE 变更不触发部署、同组部署改为取消进行中的旧任务（cancel-in-progress）、缓存 `.next/cache` 加速构建
- **图片域名**：`next.config.ts` 图片域名白名单补 `api.qijieya.cn`

### 静态导出构建加固

- **脚本改为 try/finally**：原先 `package.json` 用 `prepare && next build && restore` 串联，`&&` 在构建失败时短路，restore 永远不执行，`src/actions/*.ts` 被留在空实现状态，下一次本地开发的后台管理会拿到空数据；新增 `scripts/build-pages.js` 包装脚本，无论构建成功还是失败都保证执行 restore
- **退出码保留**：保留 next build 的退出码，构建失败时 CI 仍能正确判红；restore 自身失败时额外返回非零码，避免静默留下脏文件
- **清单请求超时**：图床清单请求增加超时控制，避免图床无响应拖垮静态导出构建
- **跨平台执行**：Next 可执行入口通过 `next/package.json` 反推解析，绕开 Windows 下 `node_modules/.bin` 批处理包装在不同 Node 版本上的行为差异

### 服务端渲染兼容与存储安全

- **服务端判空**：账号管理在服务端预渲染阶段拿不到 localStorage，加载与保存账号、读写当前账号的方法增加 `typeof window === 'undefined'` 分支，避免模块顶层实例化时抛 ReferenceError
- **Token 改会话级存储**：由 localStorage 迁移到 sessionStorage——刷新仍保留登录，关闭标签页即失效，显著缩短被 XSS 窃取后的可利用窗口；读取时自动迁移旧值并清理 localStorage 残留；代码注释明确 XOR 只是混淆、并非安全边界
- **CSP 收紧**：生产策略移除 `unsafe-eval`（生产代码不使用 eval / new Function），收窄脚本注入面；新增「开发服务器专用」策略仅额外放行 `unsafe-eval`，连接与图片来源维持线上严格策略，避免开发环境的宽松策略掩盖真实拦截问题
- **依赖与仓库整理**：`simple-git` 由 3.36 升级到 4.0.2 并改为具名导入；`.gitignore` 新增 `.trae/`，同时删除已入库的 Trae 技能配置与文档（约 4000 行），避免个人环境配置进入版本控制

### 画廊页面卡顿治理

- **缩略图管线**：图床新增缩略图生成脚本，为每张图产出宽 640 的 WebP 缩略图（559 张合计 21MB、均 38KB、最大 135KB，原图均 2.79MB、最大 27.8MB），画廊卡片用缩略图渲染，点开预览仍加载原图保证清晰度
- **清单补真实宽高**：清单条目新增 `width` / `height` / `thumb`，前端首帧即可算出正确比例；原实现只能先按 4:5 占位、图片 `onLoad` 后再校正，559 张图会各触发一次瀑布流整列重排
- **入场动画改造**：移除 framer-motion 的 `staggerChildren`（0.04 × 559 ≈ 22 秒连续动画、每帧维护 559 个动画实例），改为一次性 CSS 动画并在组件内用内联延迟把错峰上限压到 24 张，整体 1 秒内结束
- **卡片轻量化**：图片卡移除 framer-motion 包装、悬停位移与缩放特效，以及图注/角标的 `backdrop-blur`（单卡 2~3 个模糊层，559 张卡片滚动时 GPU 需每帧重算模糊），改为纯 CSS 阴影过渡与半透明纯色底
- **离屏跳过渲染**：卡片外层加 `content-visibility: auto` 与 `contain-intrinsic-size: auto 420px`，视口外卡片由浏览器跳过绘制与样式计算
- **免二次全量渲染**：客户端实时刷新回来后先比对图片签名（id + 宽高 + 是否带缩略图），与当前展示一致则直接跳过状态更新，不再让 559 张卡片整体重渲染一次
- **服务端优先走图床清单**：构建期初始数据源由 GitHub Trees API 目录树改为图床清单（带缩略图与宽高），失败仍静默回退 Trees API
- **预览缩略图条**：预览面板底部导航改用缩略图，原先 5 个 48px 格子会下载十几 MB 原图

## 优化效果

- 画廊列表图片总下载量：约 1.5GB 原图 → 约 21MB 缩略图，按单卡平均体积下降约 98%
- 卡片动画实例：559 个（持续约 22 秒）→ 24 个（1 秒内结束）
- 布局重排：559 次（图片加载后逐张校正比例）→ 0 次（清单已提供真实宽高）
- 渲染次数：首屏 + 客户端刷新各一次 → 首屏一次（签名一致时跳过第二轮）

## 注意事项

- `public/_headers` 仅对 Cloudflare Pages / Netlify 等静态托管生效，GitHub Pages 会忽略该文件，需在 Cloudflare 侧用 Transform Rules 配置同等响应头
- 搜索依赖构建期生成的 `search-index.json`，本地开发与线上部署都需要确保该文件已生成
- 播放状态的稳定标识 `songKey` 在旧版本 localStorage 记录中不存在，首次升级后仍按索引恢复，重新播放并保存后即生效
- 在线歌单接口对第三方服务有依赖，主用接口不可用时自动切换备用接口
- 画廊缩略图与清单由 `build-manifest.mjs` 生成，依赖 sharp；图床仓库的 GitHub Action 需先 `npm install --no-save sharp`，再调用 `node worker/build-manifest.mjs --root . --out worker/assets`
- 图床必须重新执行部署（`node deploy-local.mjs` 或 CI）后缩略图与宽高才会生效；未部署时前端自动回退原图，功能不受影响
- 图床清单有 5 分钟会话级缓存，同一标签页内短时间重复进入画廊不会重新拉取最新清单
- 卡片离屏跳过依赖 `content-visibility`，多列瀑布流容器下若浏览器应用了尺寸 containment，滚入视口时可能出现轻微位置跳动，可在 `GalleryClient.tsx` 移除 `gallery-card-visible` 类停用该优化
- Token 现为会话级存储：刷新页面仍保持登录，关闭标签页后需重新填写
- 生产环境 CSP 已移除 `unsafe-eval`，若后续引入依赖 eval / new Function 的第三方库，需重新评估该指令是否放行
- `.trae/` 已加入 `.gitignore` 并从版本库删除，本地目录仍保留，仅不再提交

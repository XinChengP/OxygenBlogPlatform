## 功能概述

原 Meting API (`api.i-meto.com`) 已停止服务，导致站内音乐播放器无法获取歌曲数据。本次修复替换为稳定的公共 Meting API 源，并兼容新旧版返回字段命名差异，同时同步更新安全配置。

## 主要变更

### Meting API 源替换

- **替换地址**：从 `api.i-meto.com` 迁移到 `meting.immovable.icu`（injahow 公共 Meting 服务）
- **URL 拼接修复**：重构 API 请求 URL 的拼接逻辑，避免 `&` 和 `?` 误用导致的重定向问题

### 多版本字段兼容

- **问题背景**：不同 Meting API 源返回的歌曲字段命名存在差异（如 `picUrl` vs `pic_url`、`playUrl` vs `url` 等）
- **兼容策略**：在 `neteasePlaylistService.ts` 中增加字段回退逻辑，优先读取新版字段名，找不到则降级到旧版命名
- **覆盖范围**：歌曲封面、播放链接、歌词文件等关键字段均做了双重兼容

### 安全配置同步更新

- **CSP 配置**：更新 `src/utils/cspConfig.ts` 中的 API 域名白名单
- **安全头配置**：更新 `src/utils/securityHeaders.ts` 中的资源加载域名
- **构建配置**：更新 `next.config.ts` 中相关外部域名声明

## 技术实现

| 文件路径 | 说明 |
|---------|------|
| `src/services/neteasePlaylistService.ts` | 核心改动：字段兼容逻辑重构，新增多种字段名回退 |
| `next.config.ts` | 更新远程域名配置 |
| `src/utils/cspConfig.ts` | 更新 CSP 白名单域名 |
| `src/utils/securityHeaders.ts` | 更新安全头域名 |
| `src/utils/musicConfigManager.ts` | 更新 API 源地址 |
| `public/content/music.json` | 更新预设歌曲封面地址 |

## 注意事项

- 当前使用的是公共 Meting API，若再次出现服务中断，可通过修改 `musicConfigManager.ts` 快速切换到其他 Meting 兼容服务（如 `meting.api-meting.top`）
- 安全头和 CSP 配置必须与 API 域名同步更新，否则浏览器会拦截请求
- 本次修复不影响本地已有音乐文件的播放

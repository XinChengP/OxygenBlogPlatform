# 生成产品需求文档 (/to-prd)

## 用途

当你需要：
- 将讨论的功能需求正式化
- 创建可追踪的开发任务
- 沉淀产品决策
- 与团队协作

## 工作流程

1. **探索代码库** —— 了解当前状态（如果还没做过）
2. **识别模块** —— 列出需要构建或修改的主要模块
3. **编写 PRD** —— 使用下方模板
4. **发布到问题追踪系统** —— GitHub Issues 或本地文档

## PRD 模板

```markdown
## 问题陈述
用户面临的问题，从用户视角描述。

## 解决方案
问题的解决方案，从用户视角描述。

## 用户故事
详尽的编号用户故事列表。格式：
1. 作为<角色>，我想要<功能>，以便<收益>

示例：
1. 作为博客读者，我想要文章分类筛选，以便快速找到感兴趣的内容
2. 作为作者，我想要草稿自动保存，以便防止内容丢失

## 实现决策
已做出的实现决策，包括：
- 将构建/修改的模块
- 将修改的接口
- 开发者的技术澄清
- 架构决策
- Schema 变更
- API 契约
- 具体交互

不要包含具体文件路径或代码片段（它们会很快过时）。
例外：如果原型产生的片段能比 prose 更精确地编码决策（状态机、reducer、schema、类型形状），内联在相关决策中并简要注明来自原型。

## 测试决策
已做出的测试决策，包括：
- 什么是好的测试（只测试外部行为，不测试实现细节）
- 哪些模块将测试
- 测试的先例（即代码库中类似的测试类型）

## 范围外
本 PRD 范围外的事项描述。

## 进一步说明
关于该功能的其他说明。
```

## 使用示例

**你：** /to-prd 我们讨论一下文章评论功能

**我：** 好的，让我先探索代码库了解当前状态...

[探索代码]

基于我们的讨论，我识别出以下模块：
- 评论提交接口
- 评论展示组件
- 评论数据模型

**PRD：**

```markdown
## 问题陈述
读者无法在博客文章下发表评论，作者无法获得反馈。

## 解决方案
添加文章评论系统，支持：
- 读者提交评论
- 评论列表展示
- 作者回复评论

## 用户故事
1. 作为读者，我想要发表评论，以便与作者互动
2. 作为读者，我想要看到其他评论，以便了解社区观点
3. 作为作者，我想要回复评论，以便与读者交流
4. 作为作者，我想要审核评论，以便管理内容质量

## 实现决策
- 使用 Server Actions 处理评论提交
- 评论数据存储在 JSON 文件中（与现有博客数据一致）
- 评论按时间倒序排列
- 支持嵌套回复（一层）

## 测试决策
- 测试评论提交接口的行为
- 测试评论组件的渲染
- 使用 React Testing Library 进行组件测试

## 范围外
- 实时评论通知
- 评论点赞/踩功能
- 富文本评论编辑器

## 进一步说明
- 考虑后续添加评论审核功能
- 需要防止垃圾评论的机制
```

我将把这个 PRD 发布到 GitHub Issues。

## 输出位置

- **GitHub Issues**: 创建新 issue，标签 `ready-for-agent`
- **本地文档**: `.trae/docs/prd/YYYYMMDD-功能名称.md`

## 何时使用

✅ **推荐使用：**
- 功能讨论结束后需要沉淀文档
- 需要创建可分配的开发任务
- 需要与协作者共享需求

❌ **不推荐使用：**
- 简单的 bug 修复
- 已经明确的小改动
- 探索性讨论阶段

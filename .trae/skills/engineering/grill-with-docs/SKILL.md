# 带文档的深度提问模式 (/grill-with-docs)

## 用途

当你需要：
- 开发复杂功能，需要建立清晰的领域模型
- 统一项目术语，减少沟通成本
- 记录重要的架构决策
- 确保代码与业务语言保持一致

## 与 /grill-me 的区别

| 特性 | /grill-me | /grill-with-docs |
|------|-----------|------------------|
| 文档产出 | 无 | CONTEXT.md、ADR |
| 适用场景 | 简单需求澄清 | 复杂功能、需要统一术语 |
| 持续时间 | 较短 | 可能较长 |
| 长期价值 | 即时 | 持续（文档沉淀） |

## 工作方式

### 1. 领域感知

在探索代码库时，同时查找现有文档：

**单上下文项目结构：**
```
/
├── CONTEXT.md              # 领域词汇表
├── docs/
│   └── adr/                # 架构决策记录
│       ├── 0001-选择-nextjs.md
│       └── 0002-数据库选型.md
└── src/
```

**多上下文项目结构：**
```
/
├── CONTEXT-MAP.md          # 上下文映射
├── docs/
│   └── adr/                # 系统级决策
└── src/
    ├── ordering/
    │   ├── CONTEXT.md      # 订单上下文词汇
    │   └── docs/adr/       # 订单相关决策
    └── billing/
        ├── CONTEXT.md      # 计费上下文词汇
        └── docs/adr/       # 计费相关决策
```

### 2. 提问过程中的文档更新

**挑战术语冲突：**
当你使用的术语与 CONTEXT.md 中的定义冲突时，我会立即指出：
> "CONTEXT.md 中将 '文章' 定义为已发布的博客内容，但你似乎指的是草稿状态——我们应该统一术语吗？"

**澄清模糊语言：**
当你使用模糊或 overloaded 的术语时，我会建议精确的规范术语：
> "你说的是'用户'——你指的是普通访客还是管理员？这两者在系统中是不同的概念。"

**讨论具体场景：**
当讨论领域关系时，用具体场景来验证：
> "假设一个已发布的文章被作者删除，但已经有评论了——这时候应该软删除还是硬删除？"

**与代码交叉验证：**
当你描述某个功能如何工作时，我会检查代码是否一致：
> "代码中文章删除是物理删除，但你刚才说支持恢复——哪个是正确的？"

### 3. 更新 CONTEXT.md

当术语确定后，立即更新 CONTEXT.md。格式示例：

```markdown
# 领域词汇表

## 文章 (Article)
已发布的博客内容，对公众可见。

## 草稿 (Draft)
未发布的文章内容，仅作者可见。

## 评论 (Comment)
读者对文章发表的反馈。
```

**原则：**
- CONTEXT.md 只包含领域概念，不包含实现细节
- 不要把它当作需求文档或草稿本
- 它是一个词汇表，仅此而已

### 4. 创建 ADR（架构决策记录）

只有当三个条件都满足时才创建 ADR：
1. **难以逆转** - 改变主意的成本很高
2. **没有上下文会令人惊讶** - 未来的读者会疑惑"为什么这样做？"
3. **真实权衡的结果** - 有真正的替代方案，你选择这个有具体原因

**ADR 格式：**
```markdown
# ADR 0003: 使用 Server Actions 处理表单提交

## 状态
已接受

## 背景
需要处理博客文章的创建和更新表单提交。

## 决策
使用 Next.js Server Actions 而不是传统的 API 路由。

## 原因
1. 减少客户端 JavaScript 体积
2. 类型安全更好
3. 与 React 表单集成更自然

## 后果
- 需要处理 Server Actions 的错误边界
- 学习曲线较陡
```

## 使用示例

**你：** /grill-with-docs 我要开发一个文章协作编辑功能

**我：** 好的，让我们深入梳理并建立清晰的领域模型。

首先，"协作编辑"在你的语境中具体指什么？
- A. 多人同时编辑同一篇文章（实时协作）
- B. 文章可以分配给多个作者，但同一时间只有一人编辑
- C. 其他模式？

我的建议是 B 模式，因为实时协作复杂度很高，可以先从简单的多作者支持开始。

**你：** 我选 B

**我：** 好的。那么我们需要引入一个新概念。让我更新 CONTEXT.md：

```markdown
## 协作者 (Collaborator)
被授权共同编辑某篇文章的其他作者。
```

下一个问题：协作者有哪些权限级别？
...

## 文档位置

- **CONTEXT.md**: 项目根目录或各模块目录
- **ADR**: `.trae/docs/adr/` 或模块内的 `docs/adr/`

## 何时使用

✅ **推荐使用：**
- 开发核心业务流程功能
- 引入新的领域概念
- 需要统一团队术语
- 做出重要的架构决策

❌ **不推荐使用：**
- 简单的 UI 调整
- 修复明显的 bug
- 添加配置项等小改动

# 更新日志管理 (/changelog)

## 用途

当你需要：
- 记录代码层面的功能变更或技术实现调整
- 创建符合规范的更新日志文件
- 整理版本发布说明和系统架构变更
- 为变更日志页面生成新的技术条目

**不包括：** 个人动态发布、博客文章发布、内容文本编辑等纯内容类更新

## 更新日志规范

### 文件位置与命名

更新日志存储在 `src/content/changelogs/` 目录中，文件命名为 `YYYY-MM-DD.md`。

### Frontmatter 格式

```markdown
---
date: "YYYY-MM-DD"
title: "更新标题"
type: "feature|optimize|fix|docs|style|refactor"
commits:
  - "commit message 1"
  - "commit message 2"
---
```

### 类型说明

代码中严格定义了六种类型，无其他选项：

| 类型 | 中文标签 | 颜色 |
|------|---------|------|
| feature | 新功能 | #66ccff (天依蓝) |
| optimize | 优化 | #9966ff (紫色) |
| fix | 修复 | #ff66cc (粉色) |
| docs | 文档 | #ff9966 (橙色) |
| style | 样式 | #ccff66 (黄绿色) |
| refactor | 重构 | #66ff99 (绿色) |

### 旧类型映射

代码读取时会将旧类型自动映射到上述六种之一：

| 旧类型 | 映射目标 | 说明 |
|--------|---------|------|
| perf | optimize | 性能优化类提交映射为优化 |
| chore | docs | 其他/杂项类提交映射为文档 |

**注意：** 若 frontmatter 中的 type 值不在有效列表中且无法映射，代码会默认将其视为 `docs` 类型。

### 内容结构模板

```markdown
## 功能概述

简要描述本次功能变更的核心内容和目标。

### 主要变更

#### 子分类名称（如功能模块、组件、页面等）

- 具体改动描述
- 具体改动描述

#### 另一子分类

- 改动描述

#### 其他

- 杂项改动描述
```

**格式说明：**
- 使用 `## 功能概述` 作为正文起始标题
- 使用 `### 主要变更` 包裹所有变更内容
- 使用 `#### 子分类名称` 按模块或功能分组
- 列表项使用 `- 描述内容` 格式，无需强制加粗前缀
- 如有无法归入特定分类的杂项，使用 `#### 其他` 收纳

## 成就标签系统

代码中定义了四种成就类型，自动根据提交数量和日志行数计算：

| 成就名称 | 触发条件 | 颜色 |
|---------|---------|------|
| 略感疲惫 | 关联提交数量 >= 10 且 < 20 | #7366ff |
| 肝爆了 | 关联提交数量 >= 20 | #e566ff |
| 麻雀虽小五脏俱全 | 关联提交 = 1 且 日志行数 > 55 | #ff66a6 |
| 人声鼎沸 | 预留成就类型 | #ff9966 |

支持在日志 frontmatter 中手动配置荣誉：
```yaml
honors:
  - name: "自定义荣誉名称"
    color: "bg-gradient-to-r from-blue-500 to-purple-500"
```

## 工作流程

1. **确定日期** —— 使用今天或发布日期作为文件名
2. **确定类型** —— 根据主要变更选择最合适的类型
3. **收集提交** —— 列出相关的 commit message
4. **编写概述** —— 用一两句话概括本次功能变更的核心内容
5. **分类变更** —— 按功能模块或组件划分子分类，使用 `####` 标题
6. **描述改动** —— 在每个分类下用简洁的列表项描述具体改动
7. **收纳杂项** —— 无法归类的改动放入 `#### 其他` 分类

## 使用示例

**你：** /changelog 记录今天的评论系统集成

**我：** 好的，我将根据项目规范创建更新日志文件...

```markdown
---
date: "2025-11-08"
title: "评论系统集成"
type: "feature"
commits:
  - "添加Giscus评论系统组件和配置测试页面"
  - "更新Giscus配置信息，使用实际的仓库和分类ID"
  - "优化Giscus评论组件的夜间模式适配"
---

## 功能概述

集成Giscus评论系统，支持在博客文章下方显示评论区，优化夜间模式适配。

### 主要变更

#### 评论系统
- 添加Giscus评论系统组件和配置测试页面
- 更新Giscus配置信息，使用实际的仓库和分类ID
- 优化Giscus评论组件的夜间模式适配

#### 其他
- 增加歌单
- 删除不再需要的代理部署工作流文件
- 删除剩余的评论相关组件和测试页面
```

## 何时使用

✅ **推荐使用：**
- 完成代码功能开发后记录技术变更
- 发布版本前整理系统更新说明
- 需要按规范生成新的日志文件
- 整理一段时间内的架构或技术变更

❌ **不推荐使用：**
- 发布新的个人动态（moments）
- 发布新的博客文章（blogs）
- 仅修改了文本内容或错别字
- 临时调试代码，不会合并到主分支
- 个人本地实验性改动
